# 商业版最小后端：需求、架构与验收

版本：设计稿 0.2；日期：2026-10-28；状态：**评审后设计决议；服务端 MVP 已实现（内测），客户端未接入、发布门禁未通过**。实施对账见 [29](29-cloud-backend-implementation.md)。本文是商业云 MVP 的设计基线，不表示现有客户端或服务已经通过验收。

适用范围：面向普通用户提供可选账号、云备份和单人多设备同步。核心训练与饮食记录继续本地优先、离线可用。原单人自托管模式继续独立存在；不要求现有用户迁移或登录。本设计不包含社交、教练、支付、内容管理、医疗建议和 AI 云代理。

5. 本文是商业化增量设计，不把 [00](00-v1-baseline.md) 所述无账号单机基线改为强制账号。云服务启用前，本机默认数据不上传。

## 2. 产品需求与用户路径

| ID | 需求 | 首版边界 |
|---|---|---|
| CB-F01 | 可选账号 | 采用邮箱一次性验证码注册/登录；首次验证即创建账号。无账号仍可使用本地核心记录。支持当前设备退出和远程撤销其他设备。 |
| CB-F02 | 授权云备份 | 登录不等于上传；用户看到数据范围后主动开启。界面显示本机保存状态、云同步状态、最近一次成功时间和可操作错误。 |
| CB-F03 | 换机恢复 | 新设备登录后，预览云端数据概要，显式选择恢复；先在本机持久化成功再显示完成。网络故障或校验失败不得覆盖本机。 |
| CB-F04 | 多设备 | 每账号首版一个云数据集；离线时本地可写。前台启动、回到前台、本地提交后及手动操作触发同步；后台执行仅尽力而为，不承诺实时。 |
| CB-F05 | 冲突处理 | 基于共同基线比较；保留双方和基线，独立修改可安全合并，无法确定的冲突交由用户处理；不得按时间或最后写入静默覆盖。 |
| CB-F06 | 自主权 | 导出本地数据；可关闭云同步并保留本地；提供清空云数据、注销账号，各自明确范围。用户自行保存的导出文件不由服务端删除。 |
| CB-F07 | 信任与安全 | 明示哪些数据上传、服务商及保留策略；保护凭据和传输、隔离账号、限制访问、提供审计与故障恢复。无需连接 AI 服务。 |

### 2.1 登录、启用与切换

- 验证码发往用户输入的邮箱；发码与验证对已注册和未注册地址给出相同的外部响应。验证成功后签发设备会话。邮箱不可访问时首版不提供自助重置或客服直接改绑，仍可使用和导出设备上的本地数据；如以后提供人工找回，必须另定可证明所有权的核验方案并完成威胁评审。客服仅能提供操作协助，不能凭邮箱或截图授予账号访问权限。
- 开启云同步前展示将上传的类别（训练、饮食、体重、计划、目标、饮水及其他实际快照字段），展示必要的服务提供方及用途；明确提醒和个人资料中可能含健康相关信息。仅用户确认后上传。数据收集与同意界面及适用地区要求在上线前由专业人员审核。
- 空云端 + 非空本机：预览概要，用户确认后以该本机数据初始化。空本机 + 非空云端：用户确认恢复。双方均非空且无共同基线：预览双方数据，允许导出本机、选择使用云端或用本机初始化/替换；所有覆盖操作先保留本机可恢复副本并明确另一侧将被替换，不提供没有可靠共同基线的自动合并。云端替换必须以当前 revision 条件写入，变化时重新预览。
- 切换账号或切换自托管/商业云时，先暂停同步并显式选择数据集；待同步数据和检查点按服务、账号、数据集及代次隔离。用户不得因登录另一账号自动上传或覆盖原数据。本机原始数据需保留，可导出后再切换。
- 退出登录清除本机登录凭据并停止云同步，不默认删除本机业务数据；下次登录或切换账号重新进行绑定检查。其他设备被撤销时，联网请求被拒绝；离线设备上的数据无法由服务器远程擦除，应告知用户自行清除。

## 3. 架构与职责

```text
Android / HTTPS PWA
  页面 → 本地应用服务 → 本地事务存储（事实、同步意图、检查点、冲突副本）
                         ↓ 本地提交后，异步同步
                  商业云同步适配器 / 单人自托管适配器（选择其一）
                         ↓ HTTPS
                  商业云 API（模块化单体）
                  ├─ 账号、验证码、设备会话
                  ├─ 数据集授权、版本条件写、幂等
                  ├─ 快照历史、删除任务、审计
                  └─ 监控告警、备份与恢复
                         ↓
                  PostgreSQL（事务型事实和版本）
                         ↓
                  加密的独立运维备份存储
```

建议采用单体服务和托管 PostgreSQL；具体语言、云厂商、邮箱服务与地区在实施前决策。数据库中存储每次提交的快照及相关元数据，**当前版本、上一版本、版本号和幂等结果在同一数据库事务提交**。不把数据库事务外对象存储写入描述成原子操作；运维备份异步生成，失败告警并阻止上线。采用托管身份服务可以减少认证实现工作，但其设备撤销、邮箱恢复、数据驻留和导出删除必须满足本文验收。

本机提交与同步解耦：先将业务事实及待同步意图可靠提交，再显示本机已保存；联网后上传。网络失败不回滚已保存的训练记录。上传成功只确认请求携带的本地 generation，上传期间产生的新记录仍显示待同步。

前台本地提交后合并 5 秒内的变更再上传；持续编辑时最多等待 30 秒发起一次，用户手动同步不等待。提交本机不因等待上传而延迟；前台恢复先比对服务端，再按需上传。后台无运行保证，回到前台或手动同步后继续。整份快照的频率、带宽和服务成本必须在目标机及弱网实测，不达标则调整节流或协议，不能牺牲本地保存。

### 3.1 数据边界与模型

| 对象 | 关键字段 / 约束 |
|---|---|
| Account | 随机不可猜测 `accountId`、邮箱验证状态、账号状态、创建时间；邮箱不是数据授权依据。 |
| DeviceSession | `sessionId`、`accountId`、设备显示名、创建/最后使用时间、撤销状态；设备名由客户端提供，仅供展示。 |
| CloudDataset | `accountId` 唯一、`datasetId`、`epoch`、状态 `never_initialized/active/deleted`、当前 `revision` 和 `snapshotHash`；账号归属只从服务端认证上下文决定。 |
| SnapshotVersion | `accountId`、`datasetId`、`epoch`、`revision`、schema/rule version、内容、哈希、创建时间；账户+代次+版本唯一。 |
| IdempotencyReceipt | 按账号、方法、路径及幂等键隔离；保存请求哈希、条件、代次和原结果，保留 7 天。不得跨账号重放结果。 |
| DeleteJob / Audit | 删除请求、执行状态、截止时间和不含业务正文的审计；最小化保留。 |
| LocalCheckpoint | 服务标识、账号 ID、datasetId、epoch、共同基线快照及哈希、远端 revision、本机 generation、在途请求；按绑定隔离且不进入业务快照。 |

云端可读取明文业务快照以进行版本校验、恢复和支持；传输与服务端存储加密**不等于端到端加密**，隐私说明不得宣称服务方无法读取。首版不上传模型 Key、登录凭据、同步 token、设备密钥、同步检查点、冲突副本、未确认草稿和可重算投影；提醒设置等是否跨设备同步以实际字段清单及用户提示为准，通知权限与排程状态是设备私有数据。

## 4. 云同步契约

### 4.1 快照与版本

- `snapshotSchemaVersion`、`ruleVersion` 和 `canonicalizationVersion` 分别标识结构、业务规则与规范化编码；不得把它们与 API 版本混用。服务端只接受明确支持的版本；遇到未来版本时返回 `VERSION_UNSUPPORTED`，客户端保留本地和待同步数据，不降级或清空。
- 已有客户端快照顶层包括 `schemaVersion`、`ruleVersion`、`datasetId`、`createdAt`、`accountingTimezone`，`records` 包括 profile、sessions、weights、foods、water、waterGoalMl、reminders、occurrences、weekGoals、customTemplates、bodyGoalGrams、targetKcal、targetProtein、weeklyGoal、activeTemplateId、activeTemplateSince；部分字段可缺省。商业云上线前逐字段冻结名称、缺省/null、删除和迁移规则，并用实际代码和导出逐项核对；不能以此概览代替最终 schema。内置内容按版本引用并保证客户端可获得；自定义内容必须进入快照或明确列为阻塞项。历史导出可能有不同删除语义，不视为同步基线。
- 以规范化后的 UTF-8 内容算 SHA-256；服务端独立重算，拒绝不一致。规范化实现及测试向量必须在开发前固定，覆盖对象键、数组顺序、数字、Unicode、null 与缺省。当前代码与旧 ADR 对规范化有差异，不可直接宣称二者兼容。相同版本的跨平台实现必须产出相同字节。
- 记录级删除使用可同步 tombstone，确保长期离线设备不能复活旧记录。实际字段逐项核对：无稳定 ID、删除标记、引用或合并语义的字段不能加入自动三方合并，必须先完成模型迁移或进入人工处理。**哈希本身不是共同基线内容**；安全合并需持久化上次共同快照。
- 首版以整份快照条件写为主，不承诺实体级增量同步。初始候选上限为未压缩 64 MiB，服务端与客户端均校验；该数值是待验证设计值而非容量保证。须以真实字段、三年及压力数据、端侧序列化内存、传输、存储费用和并发测试确定可用上限；超限返回 413、保留本地数据并提供导出。若不能满足门禁，发布前调整方案，不裁剪历史。

### 4.2 接口与并发

所有云端接口 HTTPS；`Cache-Control: no-store`；认证上下文决定所属账号，客户端提交的任何 accountId 均不作为授权依据。具体 JSON schema 和 OpenAPI 在编码前冻结并以契约测试验证。

| 接口 | 语义 |
|---|---|
| `POST /api/cloud/v1/auth/code` / `verify` | 发验证码、验证并建立设备会话；统一对外响应、限流，不输出验证码。 |
| `POST /api/cloud/v1/auth/refresh` / `logout` | 刷新或撤销当前会话；设备列表及撤销使用 `GET /api/cloud/v1/devices`、`DELETE /api/cloud/v1/devices/{id}`，均需认证和归属校验。 |
| `GET /api/cloud/v1/dataset` | 返回 `never_initialized`、`active` 或 `deleted`，以及适用的 datasetId、epoch、revision、hash；active 时返回快照。无权访问不泄露他人信息。 |
| `PUT /api/cloud/v1/dataset` | 初始化使用 `If-None-Match: *`；更新使用 `If-Match` 强 ETag，均带幂等键与当前 epoch。服务端校验授权、版本、大小和快照；条件不匹配 412。 |
| `GET /api/cloud/v1/dataset/versions` / `GET /api/cloud/v1/dataset/versions/{versionId}` | 列出当前账号未过期且未删除的可恢复版本及其 datasetId/epoch 概要，按需读取内容并校验归属。同数据集的恢复按当前 ETag 条件写并产生新 revision；恢复替换前的不同数据集使用显式 replace 流程。 |
| `POST /api/cloud/v1/dataset/replace` | 双方非空且无基线时，用户明确选择本机替换云端后使用；携带当前 ETag、当前 epoch、幂等键和新快照。成功保留旧云版本供恢复，事务内绑定新 datasetId 并推进 epoch，使其他设备重新绑定。不得用普通 PUT 绕过 datasetId 检查。 |
| `POST /api/cloud/v1/dataset/reinitialize` | 仅对 deleted 状态可用，用户确认后使用当前删除代次的条件令牌初始化新 datasetId/epoch；旧设备请求不能使用旧代次重新创建。 |
| `DELETE /api/cloud/v1/dataset` | 需要近期验证、当前条件令牌及幂等键；使旧代次立即失效，撤销待处理写入，按第 5 节删除。 |
| `DELETE /api/cloud/v1/account` | 需要近期验证；撤销所有会话、使旧代次失效、创建账号及数据删除任务。可通过账号已验证的联系方式获取完成状态。 |

每次写入按账号及数据集串行化：认证及授权 → 限大小和解析、计算覆盖方法/路径/账号/epoch/条件/请求体的请求哈希 → 事务内检查当前状态与 epoch → 查询普通幂等记录（同键同请求返回原结果、异请求 409）→ 检查条件 → 校验业务快照 → 写历史版本、当前版本及幂等结果并原子提交。撤销账号、删除或 epoch 变化优先于旧普通写入回执。**唯一例外**：replace、reinitialize 或 delete 成功后改变 epoch，其响应丢失时，7 天内允许同一账号、同一方法路径、同键同请求在该操作直接产生的结果状态下查询该操作专属回执并返回原结果，不再次执行；之后再发生替换、删除或注销，则旧回执不能返回现存成功状态。注销撤销会话后不能用旧会话重试，使用独立删除状态凭证查询。过 7 天后客户端先读取当前状态和哈希再决定下一步，不能盲目重试旧写入。

返回分类：401 需重新登录；403 无权限；409 数据集不匹配/已删除/幂等键复用；412 版本变化；413 超限；422 数据或引用无效；428 缺条件；429 限流；5xx 服务故障。错误不包含业务正文；客户端将可重试故障保留为待同步，权限、版本及冲突进入明确阻塞状态。

### 4.3 冲突与恢复流程

1. 从本机持久化快照创建固定请求并记下 generation、base、epoch 和幂等键；同一绑定同一时刻最多一个在途写入。多标签/进程使用本地事务租约，租约过期可恢复。
2. 比较本地、远端与共同基线：仅本地变化可条件上传；仅远端变化可在确认本地未变后保存远端；两边相同可确认；双方变化或 412 进入冲突处理。
3. 合并前持久化本地、远端和共同基线。仅对具备稳定 ID、完整删除语义且已通过合并规则测试的实体做三方合并；一侧未改取另一侧、不同实体改动可合并。同实体双改、删除与修改、同日体重、同周目标、多个活动会话及引用约束冲突必须呈现并由用户选择。未覆盖的字段禁止自动合并。
4. 用户确认前复核本机 generation、远端 revision 和 epoch；变化则重新计算预览。本地先提交合并结果并保留双方副本，再条件上传；再次 412 则重新进入冲突，不能强制覆盖。若用户选择整体保留某一侧，界面说明未选中的修改不会进入当前结果，提供双方导出与恢复入口。
5. 恢复历史云版本也必须预览并创建新的版本，不直接把数据库回滚到旧 revision；当前设备有未同步数据时先保护本机副本。草稿、登录密钥和设备级通知不会通过云恢复。

## 5. 备份、删除与运维

### 5.1 两类备份

- **用户可恢复版本**：当前快照以外，保留最近 30 天内最多 10 个不同的此前版本，按创建时间从新到旧轮转；若 30 天内没有此前版本，则无可恢复历史版本。当前快照不占 10 个名额。容量配额及是否收费待定，上线前须公示，容量不足拒绝写入并保留本地，不静默减少已承诺的保留份数。用户可预览并手动恢复；用户删除云数据时这些版本一并删除。版本轮转不得影响当前快照事务。
- **运维灾备**：数据库每日全量备份并配置持续日志归档，备份加密、独立权限和异地或独立故障域存储；保留最长 30 天。备份完成和恢复演练必须有证据。目标 RPO ≤ 24 小时、RTO ≤ 24 小时，是上线目标而非现状保证；恢复时恢复到隔离环境、校验数据后切换。发生全库灾备恢复时须重建删除台账、撤销受影响会话并旋转服务恢复代次，阻止旧条件写；无法确保删除台账时禁止对外开放写入。**即使灾难前显示过已同步，恢复点之后的云端写入也可能丢失**：受影响设备重新认证后，必须对照本地和恢复后的云端并重新确认，不能把本地当作无变化而自动覆盖；只存在于云端且未被恢复的内容可能无法找回，需告知用户。

### 5.2 清空云端与注销

清空云端：近期验证并确认范围后，服务端事务内将数据集置为 `deleted`、推进不可回退的 epoch、撤销旧写入资格，并立即停止在线快照及历史版本的读取；删除在线当前快照、历史版本和缓存，目标 24 小时内完成。此后旧设备上传、旧幂等重试以及旧的 `If-None-Match: *` 均不能复活数据。若用户日后主动重新启用，使用当前删除代次令牌和新数据集/代次初始化；其他旧设备需重新绑定、预览。

注销账号：先支持导出提醒，近期验证后停用账号、撤销全部会话并推进代次；在线个人数据、历史版本和相关凭据目标 24 小时内删除。最小删除台账仅保存阻止复活和审计所必需的随机标识及时间，不保留业务内容；重新注册即新账号，不自动找回旧数据。运维备份中的相关副本随轮转最迟 30 天删除；备份恢复时必须先应用独立、可恢复的删除台账再允许访问或写入。用户自存导出和未联网设备上的本地副本不受服务端删除控制。界面分别显示已受理、在线数据删除完成和备份到期时间，失败进入告警与人工处理。

删除台账须与账号停用/代次变化作为同一事务提交，并在返回受理成功前通过跨故障域同步复制保证已持久化；复制或事务失败不得确认删除成功（响应丢失或提交结果未知时，查询任务状态，不假定回滚）。独立只读归档持续保存台账及有序位置，用于全库恢复时追平；恢复时需证明台账连续且至少覆盖恢复到对外服务的时间点，否则服务保持关闭、告警并人工处理。仅在原数据库中写一条记录后异步复制不能满足本要求。

注销请求前客户端生成并本机持久化安全随机的 256 位状态查询凭证；请求经 TLS 发送凭证，服务端仅存摘要，事务内与对应删除任务绑定。这样即使注销成功响应丢失、旧登录会话已失效，原设备仍可用该凭证查询任务；它只能查询有限状态、不提供业务数据，有效期覆盖删除窗口，到期失效。服务端不得以邮箱或任务 ID 单独授权查询；该凭证不进 URL、日志或普通导出。设备丢失时仅可通过事先验证且符合数据最小化要求的通知渠道提供状态，不能因此恢复账号访问权。

### 5.3 认证与安全

- 邮箱验证码使用安全随机生成的 6 位数字，10 分钟有效、单次使用、每次挑战最多 5 次错误；发码和校验按邮箱、设备与来源限流。服务端仅保存带服务端密钥的验证码摘要，不以无密钥哈希保存低熵验证码；验证码仅出现在用户邮箱及验证请求中，不进入 URL、日志或分析。清空云端和注销须使用 10 分钟内的独立近期验证，验证码与操作类型绑定且单次使用；具体限流阈值、邮件服务及滥用监控上线前压测调整。
- 短期访问凭据（目标 15 分钟）和可轮换的长期刷新凭据（目标 30 天）；刷新令牌安全存储、服务端保存不可逆摘要并支持撤销及重放检测；并发刷新须有明确处理，防止误撤销正常会话。账号注销和设备撤销必须使服务端会话立即失效，受保护请求逐次检查会话状态，不能只等访问令牌过期。
- Android 通过经验证的系统安全存储保存凭据；PWA 不承诺对同源恶意脚本安全，需 CSP、XSS 防护、受限来源和最小权限；不得将凭据写 URL、普通导出、业务快照、日志或分析事件。具体浏览器会话方案及跨站请求防护在实现前通过威胁评审。
- 数据库、备份与传输加密；密钥与数据分离，权限最小化并定期轮换。运营和开发人员默认无法直接查看用户快照；受控支持流程须有授权、审计与最小范围。监控只使用错误码、请求 ID、版本与耗时，不记录邮箱验证码、凭据、食物/训练/身体内容。
- 区域、数据处理商、隐私政策、账号注销流程及适用要求，在目标市场确定后上线前完成审核；本文不是法律合规结论。

# v1 饮食记录与营养目标边界

版本1.0；2026-10-23；待实现。范围[00](00-v1-baseline.md)，实体[11](11-data-model.md)，验收[12](12-v1-acceptance.md)。原动态调整规则已归档，不构成v1算法处方。

## 1. 实际、计划、完整度

FoodLog是用户确认的实际摄入；MealPlan仅作参考，照餐单吃需明确确认复制为独立记录。未记录不等于0，不完整不等于全天，不使用计划值补缺失。

NutritionDay四值：missing、partial、complete、confirmedFasting。第一条实际日志使missing变partial；用户确认全天后为complete；增改删餐使complete失效，回partial（无条目则missing）。confirmedFasting只能显式确认且无食物；新增食物回partial。

每日与周展示同时显示记录覆盖：例如“本周3个完整日，2个部分日”；周均只对完整日单独报告并注明分母，不以未记录天为0平均，不把完整日均值宣传为全天候真实均值。

## 2. 记录路径

- 无Key、离线可手工记热量与蛋白、查本地食物、最近/收藏、复制餐次。
- 食物条目保存营养来源/版本、生熟或制备状态、数量与单位；口语份量可校正，不能把一碗当固定权威克数。
- 文字解析可选：实体/份量草稿→本地候选匹配→用户核对→落实际记录。未知项可手工填写，不强迫模型编数字；失败保持原文。
- 方法标记label/weighed/database/estimated/manual；不声称exact。估算区间仅在有依据时显示，不能固定宣称所有中餐误差15–30%。
- 用户校正只保存该记录和可显式复用的份量偏好，v1不后台学习油量。
- 编辑删除重算合计和完整度，保留修改来源；食物库更新不重算历史已确认记录。

## 3. 目标与餐单

手工记录无需营养档案。启用公式初始估计前需完整有效的适用年龄范围、身高、体重、公式所需性别参数和活动水平；缺少则显示未计算，允许手工目标。只针对一般健康成年人；特殊健康状况不自动给处方。

初始估计可采用有明确来源的Mifflin-St Jeor及活动系数，但公式、参数、目标偏移、适用范围和摄入保护策略必须形成版本化NutritionPolicy，经内容审核及边界测试后才能发布。取消旧文档固定1200/1500与“永不低于BMR”两套冲突的直接执行规则；不在本轮用另一套未经审核数值代替。

NutritionPolicy需列出：公式及引用、输入单位与范围、活动系数、目标参数、极值/冲突处理、不可自动建议的人群、提示语、审核记录和版本。实现前未提交此材料不能开启自动建议；属于AC-N06发布前置，不是允许开发者临时填数。

生成目标只能是建议，用户采纳后新建NutritionTargetVersion并给生效日期；不覆盖历史。自动计算如无可行的宏量组合应报告无法给建议并回手工，不用单独抬高碳水制造总热量矛盾。

过敏、素食程度、不吃的食物和未确认限制单独管理：未确认饮食限制不生成自动餐单，仍允许手工记实际；确认后以确定性过滤全部原料，无法验证则不建议该餐，不能只靠提示词或免责声明。

## 4. v1不执行的自动调整

自适应TDEE、按睡眠自动减量、疼痛统一禁用14天、单餐超额补偿、训练后窗口处方、后台油量学习不在v1。AI解释不等于可绕过此范围自动写入目标。

未来研究自适应算法时必须有：输入完整度、冷启动、暂停/恢复、体重异常与缺失处理、估计不确定性、调幅边界、回放与试用验证、用户采纳和回退。不能承诺第3周自动接管，也不能把漏记自动校正成真实消耗。可参考[MacroFactor官方的数据不足处理](https://help.macrofactorapp.com/en/articles/74-expenditure-version)，但不复制其门槛作为本算法有效性证据。

## 5. 食物库与内容发布

离线内置为主，不要求用户运行MCP或Node。候选数据先核验数据本身的再分发权、来源与版本，不因仓库代码MIT就认为数据可商用。发布包包含清单、署名与校验和；未核实的数据不发布。

验收不以1677或1000条作为硬数量指标：全部内置餐单原料可检索、别名可匹配、数据版本可追溯，陌生食物有手工入口。明确生/熟、可食部分和每100g基准，不能混合计量。

验收关联：AC-N01–N08、AC-I01–I04、AC-C04、AC-AI01–AI04。数值策略与内容许可仍需实现阶段提供审核证据；本轮文档不把它们标为通过。

# 证据 · AC-N04 / N05 / N02 / F03（过敏原与营养策略）

对应 G0 阻塞 #1 的最后两项内容缺口。

## 1. 过敏原标注（AC-N05）

### 交付内容

| 项 | 值 |
|---|---|
| 过敏原类别 | 8 类（麸质、蛋、奶、大豆、花生、坚果、鱼、甲壳类） |
| 标注食物 | 57 条（食物库全部） |
| 标注总数 | 456 条（57 × 8） |
| 三态 | contains / mayContain / free |
| 字段 | `foodId, code, presence, sourceRef` |
| 位置 | `src/content/allergens.ts` |

### 标注原则（保守优先）

1. 只有配料明确且单一才标 `free`（如鸡胸肉、米饭、西兰花）；
2. 加工食品（面包、挂面、曲奇、奶茶、饺子）因辅料与产线不可控，标 `mayContain`；
3. 复合菜品（麻辣烫）底料与蘸料成分不可控，**全部 8 项标 mayContain**；
4. 未收录的食物在过滤时按 `mayContain` 处理。

**采样核对（部分）**：

| 食物 | 过敏原 | 标注 | 依据 |
|---|---|---|---|
| 牛奶（全脂） | 奶 | contains | 配料即乳 |
| 鸡胸肉 | 麸质/蛋/奶… | free | 单一肉源，未加工 |
| 全麦面包 | 麸质 | contains | 小麦粉 |
| 全麦面包 | 奶/大豆 | mayContain | 商用面团常含乳粉与大豆粉 |
| 虾仁 | 甲壳类 | contains | 物种本身 |
| 三文鱼 | 甲壳类 | free | 鱼类非甲壳类 |
| 混合坚果 | 坚果/花生 | contains | 成分表含两类 |
| 麻辣烫 | 全部 8 项 | mayContain | 底料与蘸料不可控 |
| 乳清蛋白粉 | 奶/大豆 | contains | 乳清为乳制品，多数含大豆卵磷脂 |

## 2. 营养策略参数（AC-N02）

### 交付内容

| 项 | 值 |
|---|---|
| 参数项 | 12 项（活动系数、蛋白区间与默认、缺口/盈余、热量双下限、脂肪区间、取整规则、体重变化上限） |
| 排除声明 | 6 条（孕妇哺乳、未成年、肾病、糖尿病、进食障碍、BMI<18.5 减重） |
| 每条参数 | 含 `basis`（依据来源）与 `appliesTo`（适用人群） |
| 位置 | `src/domain/nutrition-policy.ts` |

### 关键参数与依据

| 参数 | 值 | 依据 |
|---|---|---|
| 蛋白下限 | 1.6 g/kg | 阻力训练人群维持与增肌常用下限（Morton 等 2018 元分析区间 1.6–2.2） |
| 蛋白上限 | 2.2 g/kg | 同上；肾功异常者不适用 |
| 减脂缺口 | 15% | 温和缺口，保留瘦体重与训练表现 |
| 增肌盈余 | 10% | 减少脂肪同步增长 |
| 热量下限 | max(1.1×BMR, 1200 kcal) | 长期低于静息消耗难维持且微量营养素易不足 |
| 脂肪供能 | 20%–35% | 保障脂溶性维生素吸收，同时给训练留碳水 |
| 取整 | 热量 50 kcal / 蛋白 5 g | 避免 2137 kcal 这类虚假精确值 |

### 计算顺序固定

`TDEE → 目标调整 → 下限校验 → 蛋白 → 脂肪 → 碳水补足 → 取整`

任一步触发下限即返回 `blocked` 并附可操作建议，**不生成"凑出来的数字"**。

### 测试（23 项）

活动系数单调与区间、维持/减脂/增肌相对关系、蛋白取整、热量取整、三大营养素热量吻合、碳水非负、双下限保护、参数表完整性（每个字段都有说明）、排除声明含关键人群、目标节奏校验（合理/激进/零周期/增肌方向）。

其中一条测试抓到真实缺陷：脂肪供能上限的 `basis` 只有 10 个字，未达"必须有依据"的标准；已补全。蛋白取整同理（7 字 → 完整说明）。

## 5. 局限

| 项 | 现状 |
|---|---|
| 标注准确性 | 凭配料常识与常见工艺判断，**未经注册营养师逐条复核** |
| 抽样复核 | 要求 ≥20% 抽样，本次未执行独立复核 |
| 外食场景 | 餐厅菜品成分不可控，标注仅对"食物库条目"负责 |
| 交叉污染 | 加工食品统一标 mayContain，未区分产线等级 |
| 营养参数 | 依据公开文献与常见实践，未做临床验证 |
| 特殊人群 | 已声明不适用，但未做输入拦截（如孕期状态无法识别） |

**结论**：G0 的"内容数据缺口"已补齐，可签字；但**内容审核签字**（人工复核 ≥20%）仍需内容/营养审核角色执行，本次为开发侧自测。

# 练迹 · 商用标准严苛评估

> 视角：以"能不能上架和商业 App 正面竞争"为标准，而不是"这个项目做得怎么样"。
> 日期：2026-10-27
> 对标：Hevy（力量记录标杆）、Strong（极简快速）、Keep（中国大众）、Apple Fitness（系统级完成度）、Fitbod（自动化）、MacroFactor（营养算法）
> 方法：当前工作区真实运行 + 逐屏截图（浅色/深色/360/390/1024）+ 代码核对 + 与商用产品的能力基线逐项比对
> 说明：本轮评审期间，上一轮 PM 报告里的若干 P0（补录可见、完成度阈值、休息计时持久化、从零开始建计划、删除撤销）已被修复；本文只针对**当前仍存在**的差距，不重复已修项。

## 0. 判决

**加权得分：5.0 / 10（加权 4.95）。**
商用中位：8.1。各维度最佳值加权：9.2。

> **这是一个有灵魂的独立产品，还不是一个能上架竞争的商业产品。**

它有商用产品买不到的东西：明确的视觉气质、本地优先的数据伦理、比商业 App 更严谨的周目标模型、逐组"上次"参照。这些是真资产。

但它缺的是商用产品的**骨架**：第一次就成功的引导、训练现场的完整工具链、可信的进步可视化、系统级存在（通知/小组件/手表）、营养数据库、账号与商业化、无障碍与多语言。缺任何一项都不致命；**同时缺，就不是一个层级的产品**。

### 三个"第一分钟就输"的点

1. **打开先看到 42 场别人的训练**。示例数据是诚实的，但它把"我的数据"和"演示"混在同一个首页，新用户第一反应是"这是我吗"。
2. **没有一个"推荐我现在做什么"的答案**。今日页给了一个计划卡，训练页给四个训练日，周目标给 0/3 和一段规则说明——用户要自己做选择题。Hevy/Keep 在这一步给的是"就练这个"。
3. **第一屏有 3 段解释性文案**（"原始 4 项 → 调整后 3 项 · 最低目标 3 项"、"未记录不等于 0"、"这场只记录了训练次数…"）。商用 App 在第一屏只放行动，解释放到二级页面。

### 三个"其实已经商用级"的点

1. **数据安全**：导出/导入/预览/合并/替换/自动备份/墓碑恢复/双副本——比多数商业 App 完整。
2. **周目标模型**：顺延不减目标、豁免留原因、跨周不搬债务——比 Hevy 的简单 streak 更有想法。
3. **记录现场的核心**：逐组上次参照、预填、休息计时、四种跟踪模式——这一块有 8 分。

## 1. 评分卡

分数是评审判断（1–10），不是用户调研；但每一项都能在本文或截图里找到依据。

| 维度 | 权重 | 练迹 | 商用中位 | 最佳 | 差距一句话 |
|---|---:|---:|---:|---:|---|
| 首次体验 / 激活 | 15% | **4.5** | 8.0 | Keep 8.5 / Apple 9 | 给选择，不给推荐；给解释，不给行动 |
| 记录效率 / 现场 | 25% | **7.0** | 8.5 | Hevy 9.5 | 记一组本身 8 分；缺的 40% 工具链把整体拉到 7.0 |
| 信息架构 / 导航 | 10% | **5.0** | 8.0 | Strong 8.5 | 6 个 tab、两处职责重叠、三处"数据" |
| 视觉系统 / 品牌 | 15% | **6.5** | 8.0 | Apple 9.5 | 有气质，没系统；好看不等于好读 |
| 数据 / 洞察 | 15% | **4.0** | 8.0 | Hevy 8.5 / MacroFactor 9 | 数据在，洞察不在 |
| 留存 / 生态 | 10% | **2.0** | 8.0 | Keep 9 / Apple 8.5 | 没有通知、小组件、手表、成就、社交 |
| 平台能力 | 5% | **2.0** | 8.0 | Apple 10 / Hevy 8.5 | 无 Watch、无 Widget、无 Health、无 Live Activity |
| 无障碍 / 国际化 | 5% | **3.0** | 8.0 | Apple 9.5 / Hevy 8 | 2.84:1 对比度、9px 徽标、仅中文 |
| **加权** | 100% | **5.0**（4.95） | **8.1** | **9.2** | |

> 「最佳」列取各维度最佳值的加权（不特指某一个 App）；按同一权重折算单个产品：Hevy 8.6、Strong 8.2、Keep 7.7。

**为什么记录效率占 25%**：这是用户每天真正会做的事。视觉、洞察、生态都可以后补；记录体验不行，用户第二天就不来了。这里评的是"记一组"这件事本身；工具链完整性（片计算/热身/超级组/RPE/通知）单列在 §3.2，不重复扣分。

**为什么留存只占 10%**：留存是结果，不是能力。它由记录体验、洞察、生态共同决定；单独给高权重会掩盖根因。

## 2. 第一分钟：激活路径对比

### 2.1 三条路径

**练迹（当前）**
```
打开 → 3 步引导（示例数据 → 每周几次 → 可选目标）
     → 今日页：42 场示例训练、0/3、三段说明
     → 点「开始训练」→ 进入 16 组的训练现场
```
4 次点击能开始，速度不差。问题是**中间每一步都在要求用户理解**：示例数据是什么、4 次/周意味着哪套计划、0/3 是什么意思、原始承诺是什么。

**Hevy（商用基线）**
```
打开 → 目标（增肌/减脂/力量）→ 经验 → 每周几天/器械
     → 推荐一套 routine → Start Workout → 第一个输入框
```
它也在问问题，但每个问题都直接映射到一个可执行的结果；最后给的是"你的计划"，不是"四选一"。

**Keep（中国大众基线）**
```
打开 → 首页推荐课程/计划 → 开始跟练
```
它把"选择"变成了"推荐"，把"记录"变成了"跟练"；门槛最低。

### 2.2 差距的本质

| 维度 | 练迹 | 商用基线 |
|---|---|---|
| 决策 | 用户选训练日、选模板、选是否保留示例 | App 推荐，用户确认 |
| 解释 | 先解释规则，再让用户行动 | 先行动，规则按需展开 |
| 首屏信息 | 状态 + 计划 + 周进度 + 规则 + 饮食 + 最近训练 | 一个主行动 + 一个进度 |
| 失败恢复 | 空状态仍有 0 值、默认目标 | 空状态给下一步，不显示假数据 |

**结论**：练迹的第一分钟不是"不会用"，是"要想太多"。商用产品卖的是"不用想"。

## 3. 训练现场：只覆盖了 Hevy 的 60%

### 3.1 已经做到的（这部分是真本事）

- 逐组"上次 105 kg × 6"参照，按组索引而不是只给最佳组。
- 预填上次重量，点 ✓ 保存，休息计时自动开始。
- 四种跟踪模式（负重/次数/计时/距离）正确切换。
- 换动作只影响本次；加组；跳过；结束总结。
- 离线可用，保存失败会保留输入。

这一块如果单独评分，是 8/10，接近 Strong。

### 3.2 商用基线里缺的（都是"第二次训练才会痛"的功能）

| 能力 | 练迹 | 商用基线 | 痛感 |
|---|---|---|---|
| 杠铃片计算（一边上多少片） | 无 | Hevy / Strong / Boostcamp 都有 | 高：每次加重量都要心算 |
| 热身组（warm-up set） | 数据模型有 `kind: warmup`，现场无入口 | Hevy / Strong 有 | 中：热身组会污染工作组统计 |
| 超级组 / 递减组 | 无 | Hevy / Strong 有；Fitbod 支持超级组 | 中：真实训练常用 |
| RPE / RIR 输入 | 字段存在，**界面没有输入框** | Hevy / Strong / Boostcamp 有 | 中：无法记录强度 |
| 训练备注 | 字段存在，**没有编辑入口** | Hevy / Strong 有 | 中：器械设置、疼痛、状态无处记 |
| 组间通知 / 锁屏计时 | 只有应用内计时；切后台无通知 | Hevy 有 Watch；Strong 有通知 | 高：休息时锁屏是常态 |
| 动作视频 | 只有静态示意图 | Hevy / Keep 有视频 | 中：新手看不懂静态图 |
| 1RM / e1RM | 领域层有 `e1rm()`，界面不展示 | Hevy 有 1RM 图表 | 高：力量进步的通用语言 |
| 肌群分布 / 周容量 | 无 | Hevy / Fitbod 有 | 高：练得均不均衡看不见 |
| 动作替代建议 | 无 | Hevy 有替代动作 | 中：器械被占时 |

### 3.3 现场可用性（视觉/交互）

- 顶栏 70px 在训练中不收起；800px 屏里 17% 被"练迹/日期/本地存储"占用。
- 浅色骨白 + 2.84:1 灰字，在健身房眩光下比 Hevy 的深色高对比难读。
- "上次"列 44px，360px 宽时折成两行（`105 kg ×` / `6`）。
- 每组预填值可直接点 ✓ 保存，用户以为在"确认"，实际写入了没改过的上次重量。
- "放弃"与"结束训练"并排（本轮已加确认，但位置仍然危险）。

**结论**：练迹把"记一组"这件事做到了 8 分，但把"在健身房完成一次真实训练"做到了 5 分。商用产品卖的是后者。

## 4. 进步页：数据在，洞察不在

### 4.1 三个硬伤

1. **动作趋势图是坏的**：6 根几乎等高的深色渐变柱，没有轴、没有标签、没有首尾值。视觉上像加载失败的骨架屏。
2. **力量榜按绝对重量排序**：前三是腿举 132.5 / 深蹲 105 / RDL 90，卧推 80 排第四。跨动作比绝对重量没有意义。
3. **自重动作显示 `0 kg × 0` 还标 `+6%`**：引体向上的数据是错的。

### 4.2 商用基线

- Hevy：每个动作的历史曲线、1RM 估算、PR 徽章、肌群分布、周/月容量。
- Fitbod：肌肉恢复热力图、按肌群的训练量。
- Apple Fitness：趋势（上升/下降/稳定）+ 奖项，用最少的数字讲"你在变好"。
- MacroFactor：把"趋势"做成核心产品，而不是附属图表。

### 4.3 差距的本质

练迹有**记录**，没有**解释**。用户练了 42 场，看到的是 289.5k kg 和一个坏掉的柱状图；商用 App 会告诉他"你的卧推 8 周涨了 12%，但腿部容量连续两周下降"。

**这是留存的核心**：用户不是为了记录而记录，是为了"看见自己变强"。

## 6. 视觉：杂志感 vs 工具感

### 6.1 做得好的

- 骨白 + 墨 + 酸橙，有辨识度，不像模板。
- 大字号中文标题、等宽数字，有力量感。
- 深色数据卡作为锚点，方向对。
- 日历的深色格 + 状态点，是全 app 最好的视觉。

### 6.2 不达商用标准的

| 问题 | 实测 | 商用基线 |
|---|---|---|
| 字号/字重失控 | 一屏 14 种字号、7 种字重；代码 28 种字号、10 种字重 | 一屏 3–4 种字号，2–3 种字重 |
| 圆角失控 | 18 种圆角 | 4–5 档 |
| 对比度不达标 | 次级文字 2.84:1；错误色 3.14:1 | ≥4.5:1 |
| 酸橙过载 | 主行动/完成/达标/选中/进度/品牌同一色 | 主色只做行动，状态另有一套 |
| 每页同一个黑头 | 今日/饮食/周目标/我的都以深色卡开场 | 按页面职责分配明暗节奏 |
| active tab 最响 | 底部整块酸橙 pill，抢主 CTA | 指示器弱于内容 |
| 桌面是拉宽的手机 | 1024px 下单列 1000px，按钮 800px 长 | 收窄或分栏 |
| 过度解释 | 周目标页 3 段规则说明，约 120 字 | 规则折叠，首屏只有数字 |

### 6.3 最关键的一条：场景错了

健身房的真实场景是：**强光/眩光、汗手、单手、只瞥一眼**。

- Hevy/Strong 用深色高对比，是因为在器械旁瞥一眼要立刻读到"105 × 6"。
- 练迹用骨白 + 2.84:1 灰 + 11.5px 说明文字，是"在咖啡馆读一本独立杂志"的视觉，不是"在深蹲架旁看数字"的视觉。

**这不是说必须改成深色**，而是说：训练现场需要一套"高对比模式"——更大的数字、更少的说明、更强的明暗差。现在的视觉气质很好，但它服务的是"浏览"，不是"使用"。

### 6.4 为什么 Hevy 看起来更"专业"（拆解）

1. **一屏只做一件事**：Workout 页只有当前训练，没有 hero、没有周目标、没有饮食、没有"最近训练"。练迹的今日页同时承担了 5 件事。
2. **组表是唯一主角**：大数字、行高足够、勾选明确，手指落在数字上，不是落在说明文字上。
3. **颜色只做状态**：完成/PR/警告各有色，主色不参与装饰。练迹的酸橙同时是品牌、按钮、完成、进度、选中。
4. **字号少**：标题、正文、数字三档，扫读时不需要重新校准。练迹一屏 14 档。
5. **深色高对比**：器械旁的眩光下，白底灰字是最难读的组合。
6. **系统级存在**：Watch、Widget、通知让 App 在手机之外继续工作；练迹离开屏幕就消失。

这六条没有一条是"更漂亮"，全是"更少干扰"。商用级的第一原则不是加设计，是减干扰。

## 7. 营养：50 条食物不是产品

| 维度 | 练迹 | 商用基线 |
|---|---|---|
| 食物库 | 50 条内置 | MyFitnessPal 数百万条；MacroFactor 验证库 |
| 条码扫描 | 无 | 两者都有 |
| 日期切换 | **只能记今天** | 任意日期补记 |
| 份量模型 | 按个/按克 | 份量、生熟、可食部分、品牌 |
| 宏量展示 | 只有热量 + 蛋白（碳水/脂肪采集不展示） | 三大宏量 + 纤维 + 钠 |
| 目标 | 2350/165 写死，无 UI 可改 | 按身体数据 + 目标计算，可调 |
| 自适应 TDEE | 无 | MacroFactor 的核心 |
| 趋势 | 无 | 周/月营养趋势 |

**结论**：饮食模块目前是"便签"，不是"营养产品"。要么补到可用（500+ 中餐条目、日期切换、宏量展示、目标可设），要么从主导航降级为今日页的一个卡片——不要用一个半成品占 1/6 的导航。

## 8. 平台与商业化：缺骨架

| 能力 | 练迹 | 商用基线 |
|---|---|---|
| 账号 / 云同步 | 无（自托管端点） | 手机号/微信/Apple 登录 + 云 |
| 支付 / 订阅 | 无 | 免费 + Pro |
| 客服 / 反馈 / 帮助 | 无 | 应用内反馈 + FAQ |
| 多语言 | 仅中文 | 10+ |
| 桌面 / Web | PWA，未做桌面布局 | Web 版或平板布局 |
| 隐私 / 条款 | 有文档 | 应用内可读 + 同意流 |
| 崩溃 / 分析 | 无 | 崩溃上报 + 产品分析 |

本地优先是差异化，但它不能成为"不商业化"的理由。商业化的前提是：用户先能持续用，再愿意为"更多"付费。现在的产品连"持续用"的钩子都不完整。

**可行的商业化路径**（如果坚持本地优先）：
- 买断制 Pro：¥68–128，解锁高级分析（1RM、肌群分布、周报导出）、多设备自托管同步、数据保险箱。
- 订阅制：¥18–28/月，解锁 AI 教练（需要可用通道）、营养数据库、云端备份。
- 不建议：把基础记录做成订阅——这是用户最反感的一种。

## 9. 十句会被用户杀死的话

1. "我打开它，先看到 42 场别人的训练。"
2. "它让我选'保留示例数据'，我不知道该不该留。"
3. "周目标写'原始承诺保留不变'，我是来健身的，不是来签合同的。"
4. "我练完一场，它问我'匹配哪一项'，我还要做选择题。"
5. "为什么我的引体向上是 0kg×0，还涨了 6%？"
6. "这个柱状图是加载失败了吗？"
7. "我昨天忘了记饮食，今天补不了。"
8. "我练完一场，它给我 -92.3%，我是不是越练越差？"（部分完成口径已修，但对比文案仍可能打击人）
9. "我找不到怎么联系你们。"
10. "这个 App 挺好，但我还是回去用 Hevy 了——因为我的手表、小组件、朋友都在那边。"

第 1–8 句是产品问题，第 9–10 句是商业问题。**商业问题更致命**，因为它不靠改一个页面解决。

## 10. 如果我是竞品 PM，我会怎么打它

**Hevy 的打法**：免费 + 记录速度 + 生态。它不需要做中餐、不需要做周目标，只要把"记一组"做到极致，再用 Watch/Widget/社交锁住用户。练迹在记录速度上已经接近，但生态是 0，Hevy 只需要等用户自己发现"没有手表"。

**Keep 的打法**：内容 + 社区 + 品牌。它不需要做力量记录的深度，只要让小白"跟着练"就能出汗。练迹的模板只有 12 套，没有视频课程，打不了大众。

**MacroFactor 的打法**：算法 + 数据库。它把"吃多少"做成科学，练迹的 50 条食物打不了。

**练迹唯一的防守点**：
> 数据主权（本地优先、可导出、不上传）+ 中餐 + 可解释的周目标。

这是一个真实的、商业 App 不会做的 niche：在意数据的人、吃中餐的人、想要"训练会计"而不是"社交游戏"的人。但这个 niche 很小，且这群人已经在用 Hevy/Strong 并导出 CSV。

**所以**：不要试图在 Hevy 的战场赢。把"数据主权 + 中餐 + 周目标"做成不可替代，再用商用级的完成度把这些人留住。

## 12. 两条路

### 路线 A：窄而深（推荐）

**定位**：给认真练力量、在意数据主权、吃中餐的人，一个"训练会计"。

- 保留本地优先、无需账号、可导出。
- 把"周目标 + 逐组记录 + 中餐"做成不可替代。
- 用商用级的记录现场（片计算、热身、超级组、RPE、通知）留住人。
- 用"进步可视化"（1RM、肌群分布、周报）给留下来的理由。
- 商业化：买断 Pro（¥68–128）+ 可选云备份订阅。

这条路的天花板不高，但能活，且活得有尊严。

### 路线 B：大众健身（不建议）

**定位**：和 Keep 抢小白。

- 需要课程视频、教练、社区、活动、品牌投放。
- 内容成本是现在的 100 倍。
- 练迹的视觉和团队基因都不支持。

**如果只能做一件事**：把"进步"做成可信、可读、可分享。因为记录本身没有黏性，"看见变强"才有。

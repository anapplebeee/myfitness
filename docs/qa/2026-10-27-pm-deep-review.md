## 0. 判决

**5.4 / 10。比上一轮（5.0）高 0.4，全部来自"完成判定"这一条修对了。**

上一轮四个 P0 修得干净：从零开始有周计划（实测 `原始 3 项 · 最低目标 3 项`）、补录可见、1/15 组不再算练完（今日页变成「今天只练了一半」+「继续这场」）、错过项有补做路径。这是一次真正的产品修复，不是敷衍。

但**修完 P0 之后，产品的骨架问题反而更清楚了**——因为表层糊住视线的东西没了：

> **这个 App 会算数，不会讲故事。**
>
> 它能把 1/15 组算成 7%、把容量差算成 -94.2%、把 20 个动作的 6 次重量画成 20 排灰柱。
> 但它说不出一句用户想听的话："你这周比上周多推了 2.5 kg"、"卧推停滞 3 周了，试试减量"、"你练腿的频率是上半身的一半"。

### 本轮新抓到的一条硬缺陷（最贵）

**教练页的动作趋势图，在"没进步"的时候看起来和"进步很大"时一模一样。**

实测：示例数据里每个动作 6 次训练重量恒定，20 张趋势卡渲染出 20 排**完全等高的灰柱**（`shots/deep-audit-2026-10-27/08-coach-scroll1.png`）。根因在 `src/views/CoachView.vue:207`：

```js
height: `${Math.max(12, (v / Math.max(...row.series)) * 100)}%`
```

柱高按序列最大值归一化、且最小 12%。两个后果同时成立：

| 数据形态 | 用户看到的 | 事实 |
|---|---|---|
| 6 次都是 80 kg | 6 根满高柱 | 完全停滞 |
| 80 / 80.5 / 81 / 80 / 80 / 80 | 高低错落，像大起大落 | 波动 1.2% |

**这不是"图表不好看"，是图表在说谎。** 商用产品里没有一家这么做：Hevy 用带刻度的折线 + PR 标记，MacroFactor 用趋势线 + 目标带，Strong 干脆只列历史。练迹目前这张图，是"数据在，洞察不在"这句话最literal的证据。

**四个硬数字：**

4. **今日页首屏 391px 是 hero（占 46%）**，但"今天到底练什么"这句话在中部 11px 灰字里。

- 训练页"横向溢出 8 处"是**模板卡横滑轮播**的容器内滚动，`document.documentElement.scrollWidth === clientWidth === 390`，**没有**整页横滚。真实问题只是"右侧半露无滑动提示"（P2）。

## 2. 逐模块严苛分析

每节四段：**实测现象 → 商用对照 → 判定 → 改法**。

### 2.1 首次引导 ★★☆（4.5/10）

**实测**：三步（说明示例数据 → 选计划 → 设每周次数），文案清楚，`开始使用` 后立即有周计划。

**商用对照**：Keep 首启先问"目标：减脂/增肌/塑形"，直接推课程；Fitbod 问器械条件 + 频率，直接生成训练；Hevy 一步 `Start Empty`。**共同点：用最少的提问，换一个"现在就能照做"的答案。**

**判定**：练迹把引导做成了"免责声明 + 四选一选择题"。用户走完三步，得到的仍是一张计划卡（"下肢 A · 蹲主导"）+ 一个「开始训练」按钮——**选择权交回去了**。而且引导过程中没有一句"你会先练什么"，也没有"大概需要多久"。

**改法**：
- 引导第 3 步加一屏"你的第一次训练：下肢 A · 约 45 分钟 · 4 个动作"，直接给成品；
- 结束按钮从「开始使用」改成「就这样开始练」，点了直接进训练现场（少一次点击就能练上）；
- 示例数据在引导里明示"你可以随时清空演示数据"，而不是让用户在首屏疑惑"42 次是我吗"。

### 2.2 今日 ★★★（6.0/10）

**实测**：先说对的——`0/3 本周` 环 + 「下肢 A · 蹲主导」+ 4 个动作品名 + 「开始训练/空白训练」+ 本周节奏日历条 + 累计训练 + 体重趋势 + 今日饮食。首屏一屏交代了全部关键状态，信息架构是清楚的。

**问题**（按严重度）：

| # | 现象 | 证据 | 商用做法 |
|---|---|---|---|
| 1 | 首屏有 3 段解释性小字：「原始 4 项 → 调整后 3 项 · 最低目标 3 项」「未记录不等于 0」「没练完的场次默认不计入周目标…」 | 截图 `04`/`15` | 首屏只放行动，规则收进二级页 |
| 2 | 「空白训练」在深色 hero 上是深底灰字，**几乎不可见**（对比度约 1.14:1） | 截图 `04` | 次级动作换浅色描边按钮 |
| 3 | 一屏 3 处酸橙：`本地存储` chip、`开始训练`、底部 active tab | `limeFillCount: 3` | 一屏只有 1 处（主 CTA） |
| 4 | 周节奏条里"今天"只靠一圈细描边，且"一"显示为横杠（休息日）看不出含义 | 截图 `04` | 今天用实心点 + 文字"今天" |
| 5 | 新用户首屏是别人（示例）的 42 次训练与体重曲线 | `04` 文本 | `Start Empty Workout` / 空状态 |

**判定**：今日页是**产品里最接近商用水平的一屏**——但它是"信息全"带来的错觉。真正的差距是：商用 App 的首屏让人**立刻做一个动作**，练迹的首屏让人**先读三段规则**。

**改法**：hero 里删掉「原始/调整后/最低目标」这一行（移到周目标页）；`空白训练` 提升对比度；把"今天练什么"的答案从 11px 灰字提到 h2；示例数据首屏加一条可关闭的浅色条"这是演示数据 · 清空"。

### 2.3 训练（计划 / 历史 / 动作库）★★☆（5.5/10）

**实测**：「今天练点力气」+ 计划/历史/动作库三栏 + 「+ 空白训练」+ 4 张训练日卡（含「今天」「10月28日」「已豁免」「未完成」四种状态）+ 「换一套模板」横滑卡。

**问题**：
1. **这个页面同时干四件事**：看本周计划、看模板、补录、切换模板。而"历史"和"动作库"也塞在同一个 tab 里。商用 App 的分法：Hevy 是 Workout / Routines / History 三个一级；Strong 是 Start / History / Settings。
2. **状态用词混用**：`已豁免`（周目标口径）、`未完成`（补做口径）、`今天`（时间口径）——三种语义并排做徽标，用户不知道它们的层级关系。
3. 「编辑 复制」是 22px 高的纯文字触点（`smallTargets` 实测 `h:22`），远低于 44。
4. 动作摘要被截断成「杠铃卧推、杠铃划船、上斜哑铃卧推 · 等 5 个动作」，11.5px / 3.24:1。

**判定**：**结构上把"计划"和"记录"混在一个 tab 里**，是信息架构欠债的直接体现。这也是"6 个 tab"问题的真正来源——不是 tab 多，是每个 tab 都承担了 2–3 个职责。

**改法**：`训练` tab 只放三栏（今天/历史/动作库）已经接近正确，先把"换一套模板"与"补录"收进页头 `⋯` 菜单；状态徽标统一成一套（今天 / 未完成 / 已完成 / 已顺延 / 休息）。

### 2.4 周目标 ★★（5.0/10）

**实测**：高度 1243，但**字号 18 种**（全产品最多），低对比 38 处。核心是"承诺 vs 完成"的解释型页面。

**判定**：这是练迹**模型最严谨、表达最不友好**的模块。原始承诺 / 调整后 / 最低目标三层概念，产品里没有一张图能一秒钟讲清。商用产品不用"最低目标"这个词——它们用 `2/3 天`、连续达标、周环比。

**改法**：把三层口径压成一句人话 + 一个进度条（"本周 2/3 天达标（调整后目标 3 天，因豁免 1 天）"），把口径细节放进「为什么」折叠区。

### 2.5 训练现场（LiveWorkout）★★☆（6.5/10）

**这是最贵的模块（商用权重 25%），也是问题最密集的地方。**

**实测**（390×844，`shots/11-live.png`）：

- 每组一行，横向 5 列：组号 / `105 kg × 6`（上次）/ 两个数字输入 / ✓ / ×。
- 5 行组的"上次"文字**完全一样**，且**在 105 与 6 之间换行**（`105 kg ×` / `6`）。
- 顶部全局 topbar 仍在：`练迹 / 10月27日 · 周二 / 本地存储`（70px，占屏 8%）。
- `kg / lb` 切换常驻占一整行。
- ✓ 是**无文字图标按钮**（40×40，`LiveWorkout.vue:983`），旁边还有 15px 的 × 跳过。
- 底部「放弃」（灰）与「结束训练」（深底绿字）并列。

**商用对照（Hevy 一组）**：行内只有 `组号 / 重量输入 / 次数输入 / ✓`，上次值作为 placeholder 灰字**在输入框里**；整行可点完成；顶部只留动作名 + 计时；底部一个大 `Finish`；跳过与删除在滑动/长按里。

**判定**：**核心动作（记一组）的路径没有错，但它的包装全是噪声。** 21 个 <44px 触控区、5 列布局、"上次"重复 5 遍、无文字勾选——在用户手抖、单手、组间喘息的状态下，这些噪声会直接转化成记错和误跳过。

**改法（收益最高的三项）**：
1. **删掉「上次」列**，把上次值做成输入框 placeholder（`105` / `6` 灰字），行宽回到 3 列，360px 不折行；
2. **训练中隐藏全局 topbar**（`immersive` 已有机制，`LiveWorkout` 未接线），70px 还给内容；
3. `kg/lb` 收进设置或动作名右侧的小字按钮，不占整行。

### 2.6 结束面板 ★★（5.5/10）

**实测**（`shots/13-finish-panel.png`）：`1 工作组 · 1/15 完成/计划`、红字「只完成 1/15 组（7%），默认不计入周目标」、`对比上次：-12 组 · -94.2%`、未勾选的「本次计入周目标」、`继续练 / 确认结束`。

**问题**：
1. **一屏 4 处警示红**（红字说明、`-12`、`-94.2%`、`-45.0kg`）。用户刚练完，看到的是"你搞砸了"。商用产品在这里给的是完成感（Hevy：`Workout Complete` + PR 徽章）。
2. **`-94.2%` 这个数字算得对但比较错了**：拿"1 组"和"上次完整 15 组"比容量。应改为**按动作比**：本次卧推 105×1 vs 上次卧推 105×6 → "本次每个动作只做了 1 组，不足以对比"。
3. 「1/15」的分母跨 3 个动作，用户会读成"这个动作要做 15 组"。
4. `已保存本组` Toast 压在「计入周目标」卡上（截图可见）。

**改法**：部分完成时把对比区换成"本次太少，先不比较"；分母改为当前动作（`1/5`）；警示红只留一条；PR 时给正面反馈（这是留存的关键时刻）。

### 2.7 饮食 ★☆（4.5/10）

**实测**：`1290 / 2350 kcal` 环 55%、蛋白质 `104 / 165 g` 进度条、四餐分段（早餐 08:00 / 午餐 12:00 / 晚餐 18:30 / 加餐 21:00）+ 添加 + 单条 × 删除 + 底部诚实声明。

**四个硬问题**：

| # | 问题 | 证据 |
|---|---|---|
| 1 | **目标 2350 / 165 是写死的**，`store.setTargets()` 全项目**零调用**（`grep` 只有定义与持久化） | `FoodView.vue:45` `store.state.targetKcal ?? 2350`；`seed.ts:183` 写死 |
| 2 | 用户"从零开始"后目标**仍是 2350/165**（实测两页都是 `0 / 2350 kcal`），且**无任何入口可改** | `verify-suspects.mjs` 输出 |
| 3 | 只有 kcal + 蛋白两个指标，无碳水/脂肪，也没说为什么不采 | 截图 `07` |
| 4 | **日期不能切**、条目不能改份量（只能删了重加） | 截图 `07` 无日期控件 |

**判定**：这不是"半成品模块"，是**一个没有用户输入的仪表盘**——它显示的目标是模板数字，用户却当成自己的目标。比不显示更糟：它让人误以为系统算过。

**改法**（P0 数据诚实）：`setTargets` 接到 UI（自动推荐 = BMR×活动系数 + 目标调整，允许手改）；未设置时显示「设置目标」空槽，不显示 2350。这一条同时解决 docs/00 D06 的"自适应 TDEE 未实现"缺口的前半段。

### 2.8 教练 ★★（4.5/10）——本轮最大失分点

**实测**：4483px / 5.3 屏 / 20 张趋势卡 / 47 处低对比。结构：AI 教练面板 → 周报卡 → 累计容量 289.5kg（深色 hero）→ 力量榜 Top5 → **20 张动作趋势** → 下次怎么加。

**三个致命**：
1. **趋势图零信息**（见 §0）：等高灰柱 + 归一化失真。
2. **`+7%` 的算法不可解释**：`changePct = (last - first) / first`，只有 2 个点也算百分比；用户不知道"最近 6 次"的首值是哪天。
3. **5.3 屏的纵向堆叠**：20 个动作全展开，没有"最近练过的 5 个"、没有折叠、没有排序。

**商用对照**：Hevy 的 progress 页 = 选动作 → 折线（带日期轴、1RM、PR 点、区间切换 1M/3M/1Y）；MacroFactor = 趋势线 + 目标带 + 周均。**共同点：一次只讲一个动作的进步，且图能读出方向。**

**改法**：趋势改成折线（含首尾值 + 变化 + 日期区间），只默认展开最近练的 3 个动作，其余折叠成一行"查看全部 20 个动作"。

### 2.9 我的 ★☆（4.5/10）

**实测**：体重 hero（78.2 kg + `+1.1 kg · 近 40 天` + 折线）+ 身高/目标体重/BMI 三格 + 目标三类空槽 + 体重记录 14 条 + 三栏（身体/数据/设置）。

**问题**：
1. **BMI 25.2 与"目标体重 未设置"并排**，前者按中国标准已属超重区间，但无任何解释或引导——一个显示"你超重了"却不给下一步的界面。
2. `未设置` placeholder 与真实值（176）同样式同位置，只是颜色略淡。
3. **14 条体重记录全展开**，每条一个 ×，滚动到底才能看到设置入口。
4. **三处"数据"**：本页「数据」栏 + 顶栏「本地存储」+ 数据页；语义重叠。
5. 「记录体重」（深色实心）与「本地存储」（酸橙 chip）两种按钮风格并排。

**改法**：BMI 改成区间彩条 + 一句人话（"距正常上限 1.2"）；体重列表默认折叠成 7 条 + "查看全部"；把「数据」栏并入设置，全产品只留一个数据入口。

### 2.10 数据与备份 ★★★★（8.0/10）

导出 / 导入 / 校验 / 合并 / 替换 / 自动备份 / 清空 —— **这是全产品最接近商用水平的一块**，比多数商业 App 完整。唯一建议：把"本地存储"这个技术名词换成用户语言（"你的数据都在手机上"），并把入口从顶栏 chip 移到我的。

### 2.11 AI 教练 ★★（4.0/10）

BYOK + CORS 阻塞 + 本地统计降级。当前状态下它对普通用户等于不存在（需要自己填 API Key 和代理）。**不建议本轮投入**，但要在界面上明确"AI 未配置"而不是给一个看起来能用的输入框。

**上一轮修的是"账对不对"，这一轮该修的是"话说不说得清"。**

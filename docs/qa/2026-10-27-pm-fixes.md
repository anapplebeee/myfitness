# PM 评审 P0 修复记录（2026-10-27）

对应评审：[全模块产品体验评审](./2026-10-27-pm-module-review.md)

## 1. 引导"从零开始"后周目标为空

**问题**：取消勾选"保留示例数据"后 `completeOnboarding` 清空了 occurrences，但没有重新预建；
`ensurePlanAhead` 只在 `init()` 里跑，于是新用户看到"本周没有设定计划 0/0"，刷新才恢复。

**改法**：`completeOnboarding` 末尾调用 `ensurePlanAheadImpl(state)`。

**验证**：`e2e/onboarding-goals-cache.spec.ts` 新增「从零开始后本周计划立即存在，不用刷新」——
断言 sessions=0、occurrences>0、weekGoals>0，且周目标卡分母 > 0。

---

## 2. 补录"存了等于没存"

**问题**：`buildBackfill` 生成的会话 `status: completed`，但组全是 `planned`；
`isValidCompletedSession` 要求至少 1 个 completed 工作组，于是这条记录被历史、累计、
周目标、教练**全部过滤**，toast 却说"补录已保存"。

**改法**（两条路都保证可见）：

1. 补录面板新增「每个动作几组 / 每组次数 / 重量」；填了组数就生成对应数量的 **completed** 组；
2. 不填组数 → 自动按 `completionBasis: 'selfReported'` 落库（该口径本来就能进统计）。

动作选择也从 `EXERCISES.slice(0, 18)` 改成全量 + 搜索。

**验证**：
- 单测 `amend-edge.test.ts`：补录后 `isValidCompletedSession` 为 true；不填组数走自报；
- E2E「补录后立刻能在历史里看到」：补录 → 累计次数 +1、列表出现"补录训练"。

---

## 3. 完成判定过松：1/16 组也算"练完了"

**问题**：16 个计划组只做 1 组，结束面板写 `1 工作组 · 1/16 完成/计划`，
确认后今日页"今天已经练完了"、周目标 +1。

**改法**：

- 新增 `src/domain/completion.ts`：`completionSummary()` 给出完成组/计划组、比例、是否部分完成
  （阈值 `PARTIAL_RATIO = 0.6`）；热身组不计入分母；自报训练不判部分完成；
- 结束面板：显示"只完成 X/Y 组（N%），默认不计入周目标"；部分完成时**默认不勾**"本次计入周目标"；
  一个工作组都没完成时明确说"不会计入训练次数与周目标"；
- 今日状态新增 `partial`：标题"今天只练了一半"，主按钮"继续这场"（`store.reopenSession` 把
  已结束的会话重新打开，不把数据拆成两场）。

**验证**：`completion.test.ts` 7 项；`today.test.ts` 新增 1/16 → `partial`；
E2E「只完成少量组不算练完，且默认不计入周目标」（含周目标未增加）。

---

## 4. 错过计划项没有补做路径

**问题**：训练页点过去的日卡片只弹一句"这项排在 X 月 X 日，今天开始会记为加练"，
想计入周目标得先跑去周目标页顺延。

**改法**：

- 日卡片徽标：排在过去且未完成 → 显示**「未完成」**（原来只显示日期，与周目标的"未达标"说法不一致）；
- 点击 → 弹层二选一：「补做这一项（顺延到今天）」= 顺延 + 立即开始；「只加练，不改计划」= 开始但不计入。

**验证**：手动（seed 里有过去未完成项）；行为走 `store.runPlanCommand({kind:'postpone'})`，
与周目标页顺延是同一条命令。

---

## 5. 放弃训练单击即丢弃

**改法**：`放弃` → 确认弹层（显示已记录 N 个工作组，说明不可恢复）→「继续练 / 确认放弃」。

**验证**：E2E「放弃训练需要二次确认」（点继续练后仍在训练页；确认后才退出）。

---

## 6. 休息计时离开训练页就丢

**改法**：`useRestTimer` 增加 `restore(endsAtMs)`；开始/加时/跳过时把结束时间写进
`session.restEndsAt`，重新进入按时间戳恢复。

**验证**：手动 + 类型检查（计时是 UI 状态，未加单测；`restEndsAt` 字段本就在数据模型里）。

---

## 7. 删除饮食/体重无撤销

**改法**：Toast 支持 action（`push(msg, tone, { label, onAction })`，带操作时停留 5 秒）；
饮食条目与体重记录删除后给「撤销」，按原 id 放回（`restoreFood` / `restoreWeight`）。

**验证**：手动。

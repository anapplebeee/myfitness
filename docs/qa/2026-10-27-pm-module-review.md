## 0. 结论先行

**这是一个"记录做得比教练好、计划做得比完成好"的产品。**

底层能力扎实：逐组录入、上次参照、离线可用、数据可导出、周目标模型可解释——这些是真本事，不是文档吹的。但产品层有一个明显的错位：

> **对"计划"极度严谨，对"完成"极度宽松。**

- 计划侧：原始承诺、最低目标、顺延、豁免、取消、审计原因、跨周不搬债务——像一份合同。
- 完成侧：**16 个计划组只做了 1 组，就算"今天已经练完了"，并计入周目标**（实测）。

结果用户感受到的是两件事：**记账很麻烦，达标很廉价**。这是当前最贵的产品问题，比任何一个 UI 细节都贵。

四个必须先修的 P0：

| # | 问题 | 实测证据 | 为什么是 P0 |
|---|---|---|---|
| 1 | 引导选"不保留示例数据"后，计划项为 0，周目标页显示"本周没有设定计划"，**刷新后才恢复** | 引导后 `occurrences=0 / weekGoals=0`；reload 后 `15 / 4` | 新用户第一条路径就断，且断在最核心的"周目标"上 |
| 2 | **补录保存成功，但记录在任何地方都看不到**：历史仍显示 42 次、累计仍是 42 次 | 补录后 `sessions=43`，但 `status=completed` 且所有组 `planned`；`isValidCompleted` 要求至少 1 个 completed 工作组 → 被全部统计过滤 | 直接击穿"可靠留住每次训练"的核心承诺；用户以为存了，实际等于没存 |
| 3 | 完成判定过松：1/16 组 → "今天已经练完了" + 已计入周目标 | 结束面板 `1 工作组 · 1/16 完成/计划`；今日页 `1/3` | 周目标是产品最贵的资产，被一次点击廉价化 |
| 4 | 错过计划项后，训练页没有"补做"路径，只能去周目标页顺延 | 点 10/26 那行 → toast "这项排在 10月26日，今天开始会记为加练" | "今天补上周一的训练"是真实用户最高频的动作 |

一句话建议：**把严谨从"目标审计"移到"完成事实"，把宽松从"完成判定"移到"计划调整"。**

## 1. 产品定位与核心闭环

### 1.1 定位判断

| 维度 | 现状 | 判断 |
|---|---|---|
| 目标用户 | 已有训练习惯、练力量、在意数据主权、主要吃中餐的成年个人 | 清晰，但**冷启动用户**（不知道怎么练）几乎没被服务 |
| 核心价值 | 快速记一组 → 可靠留住 → 看见进步 | 成立，且"逐组上次参照"是真差异点 |
| 差异化 | 本地优先、无需账号、周目标可解释 | 真实，但**用户感知不到**（见 §4.3） |
| 边界 | 不做社交、不做睡眠、不做自动抓取 | 克制，正确 |

### 1.2 闭环与断点

```
今日（决定练什么）
   ↓  ①
训练中（逐组记录）  ←── 休息计时
   ↓  ②
结束（本次 vs 上次）
   ↓  ③
周目标 +1 / 教练看见进步
   ↓  ④
明天还回来？
```

| 断点 | 现象 | 影响 |
|---|---|---|
| ① 决定 | 训练页点任意日卡片**直接开一场训练**，没有预览/确认；错过的日子只显示一个日期 | 误触即建会话；错过项无法补做 |
| ② 记录 | 休息计时**离开训练页就丢**（组件内 state，`session.restEndsAt` 字段没用上） | 训练中最常见的"切出去看一眼"会毁掉节奏 |
| ③ 反馈 | 部分完成也按"完成"结算；对比上次给出 **-92.3%** | 反馈不可信 + 负反馈 |
| ④ 回访 | 无提醒、无周报推送、无 streak 提醒；连续达标周埋在周目标卡第 3 个数字 | 留存完全靠自觉 |

## 3. 逐模块分析

### 3.1 首次引导

**它想解决什么**：新用户打开看到 42 场"别人的训练"，必须先说清"这是示例"，再定频率、选计划、给目标。

**我实际体验到的**

- 三步结构合理：示例说明 → 每周几次（并推导计划）→ 可选目标。第三步允许跳过，符合"不填也能开始记录"的承诺。
- 第二步把"频率"和"计划"合成一个问题，是对的——比问两遍强。
- "保留示例数据"默认勾选，并写明"取消勾选会清空示例记录，从零开始（不可撤销）"。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|
| **P0** | 取消勾选"保留示例"后，`completeOnboarding` 清空了 occurrences 但**没有重新预建**；`ensurePlanAhead` 只在 `init()` 调用。周目标页显示 `0/0`、全周"休息"、文案"本周没有设定计划" | 选择"从零开始"的用户（最认真的那批）第一条路径就断；刷新才恢复 | `completeOnboarding` 末尾调用 `ensurePlanAheadImpl(state)`；补单测 |
| P1 | 第三步问"目标体重/目标力量"，但"我的 → 身体"也能设；两处入口、两套文案 | 用户不确定以哪为准 | 引导只留一个"想练成什么样"的意图选择，具体数值留到身体页 |
| P2 | 第二步的"自定（不排计划）"会让周目标失去对象，后续首页仍显示模板日 | 选了自定的人看到"今日计划"会困惑 | 自定分支明确说明"不设周目标，只记录" |
| P2 | 第三步没有"为什么问这个"的一句话 | 目标体重是敏感信息，缺上下文会流失 | 加一行"用来算进度，不参与任何评分" |

**一句话改法**：让"从零开始"真的从零开始，且立刻有本周安排。

---

### 3.2 今日

**它想解决什么**：一眼知道今天练什么/练完没有，顺手记录。

**我实际体验到的**

- 有记录时信息层级清楚：英雄卡（状态 + 今日计划 + 主按钮）→ 本周节奏 → 累计/体重 → 饮食 → 最近训练。
- 状态机做得好：进行中 / 已完成 / 已顺延 / 休息，都有对应文案和按钮（"继续训练"/"查看这次训练"/"看本周安排"）。
- 练完后英雄卡变成"今天已经练完了 + 本次容量"，不再诱导重复开练——这是上一轮修得对的地方。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|
| **P0** | 完成 1/16 组后，标题写"今天已经练完了" | 与事实不符，周目标被廉价化 | 引入"部分完成"：`已完成 1/16 组`，主按钮改"继续这场"，周目标默认不计入 |
| P1 | 空状态仍显示 `累计训练 0 次`、`体重趋势 —kg / 0.0 kg · 近 6 周`、`0 / 2350 kcal` | 与"空状态不显示 0"的承诺相反；2350 是写死的默认值 | 无记录时整块替换为一张引导卡（记体重 / 记饮食 / 开始训练） |
| P1 | 空状态下英雄卡标题"今天没有安排"，下面却显示"今日计划 下肢 A · 4 个动作" | 自相矛盾（`todayPlan` 回落到星期几） | 无 occurrence 时不显示"今日计划"，改"按模板今天该练 X，要开始吗？" |
| P1 | 体重卡写"近 6 周"，实际取全部记录（14 条、约 4 周） | 标签与数据不符 | 按时间窗口过滤，或改成"近 14 次" |
| P2 | "已记录 3 餐"实际统计的是食物条目数 | 语义错误 | 按 slot 去重计数 |
| P2 | 同一周进度在今日/训练/周目标出现 3 次，措辞不同（"0/3 项完成"/"进行中 0/3"/"0/3 本周目标"） | 重复且不统一 | 今日只保留圆环；训练页用"今天"维度；周目标页用"本周"维度 |
| P2 | 英雄卡占近半屏，最有用的一句"今天练什么"在中部小字 | 首屏效率低 | 把计划标题提到 hero 标题位，容量/动作数降为副信息 |

**一句话改法**：今日只回答两个问题——"今天做什么"和"做到哪了"，其余都往下放。

### 3.3 训练（计划 / 历史 / 动作库）

**它想解决什么**：开始一场训练、回看历史、查动作。

**我实际体验到的**

- 三段式（计划/历史/动作库）覆盖了训练页的三类任务，切换成本低。
- 计划段每天一行，显示动作数、动作名、状态 chip（今天/日期/已豁免/已完成）。
- 历史段的月历很好用："13 天有训练 · 13 次 · 5 天漏做"，点某天打开当天记录。
- 动作库 104 个动作，可按肌群筛、可搜、有"要领"演示（离线图）。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|
| **P0** | **补录（默认路径）保存后不可见**：`buildBackfill` 生成 `status: completed` 的会话，但所有组是 `planned`；`isValidCompleted` 要求 ≥1 个 `completed` 工作组，于是这条记录被历史、累计、周目标、教练全部过滤。toast 仍提示"补录已保存" | 用户补录一次训练，历史仍显示 42 次、累计仍 42 次；等于没存，且没有任何提示 | ① 补录时至少录 1 组（组数/重量/次数），把该组标 completed；或 ② 不录组时自动走 `selfReported`（此时 `isValidCompletedSession` 为 true）；并补单测覆盖"补录后出现在历史" |
| **P1** | 点任意日卡片**立刻创建并进入一场训练**，没有预览、没有确认 | 想看动作详情的用户被塞进一场空训练；误触产生脏会话 | 点行 → 展开该日动作列表 + "开始这一项"；开始动作单独按钮 |
| **P1** | 错过的日子 chip 只显示 `10月26日`，不显示"未完成"；周目标页同一天却标"未达标" | 两个页面对同一事实说法不同 | 统一为"未完成"，并给"补做"入口（顺延到今天 / 记为加练） |
| **P1** | 补录只能选 `EXERCISES.slice(0,18)`，且不填组数/重量 | 做了高位下拉/平板支撑无法补录；补出来是空壳记录，无容量无 PR | 全量动作 + 至少"组数 × 重量 × 次数" |
| P2 | 历史列表固定 `slice(0,20)`，无分页/筛选/搜索 | 长期用户找不到三个月前那场 | 按月分组 + 筛选（模板/肌群） |
| P2 | 动作库无器械筛选、无"最近使用/收藏" | 家里只有哑铃的人要翻 104 条 | 器械 facet + 最近使用 |
| P2 | 模板卡下方"编辑 / 复制"是 44×22 的文字按钮 | 低于 44×44，真机难点 | 合并为一个"…"菜单 |
| P2 | "换一套模板"整段占首屏下方，低频但面积大 | 挤压高频内容 | 收进"模板管理"入口 |

**一句话改法**：把"看"和"练"分开——点行是看，按钮才是练。

### 3.4 周目标

**它想解决什么**：用可解释的方式管理"这周练几次"的承诺。

**我实际体验到的**

- 模型确实严谨：原始计划 / 调整后 / 最低目标三个数分开；顺延只改日期不减目标；豁免/取消留原因；跨周不搬债务。
- 周切换、日格状态、项目明细、单日详情、目标编辑都能用。
- 操作面板：豁免 / 取消 / 恢复 + 原因 chips + 顺延日期。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|
| **P1** | 概念与文案像内部文档："原始承诺保留不变"、"豁免与取消无限额，不需要理由也会记录"、"徽标优先：完成 › 进行中 › 未完成 › 未达标 › 待训练 › 豁免 › 休息" | 新用户读不懂，像在读规则说明书 | 用户语言：只保留"本周 3 次，已完成 1 次，还有 2 次"；规则放"为什么这样算"折叠 |
| **P1** | 点项目打开的面板，最显眼的是"豁免 / 取消"（两个削弱目标的动作），"顺延"在最下面，且**没有"开始这一项"** | 引导用户缩小目标，而不是完成目标 | 面板顺序改为：开始训练 → 顺延 → 豁免/取消（收进"更多"） |
| P1 | 日格徽标 9px、日期 10px；"未达标"与"豁免"靠颜色区分 | 真机可读性差 | 徽标 ≥11px，状态用图标+文字 |
| P2 | "调整最低目标"是卡片上的常驻按钮 | 目标可以随时下调，削弱承诺感 | 收进"…"，并要求填写原因（已有） |
| P2 | 新用户第一次进来就看到"原始 4 项 → 调整后 3 项"（示例数据里有一条被豁免） | 以为是系统出问题 | 示例数据不要预置"豁免"状态 |

**一句话改法**：周目标是"这周我还差几次"，不是"一份可审计的合同"。

### 3.5 训练中（LiveWorkout）

**它想解决什么**：在健身房单手、快速、不出错地记完一组。

**我实际体验到的**

- 这是全产品最扎实的一屏：每组预填上次重量、左侧"上次 105 kg × 6"逐组参照、大号数字输入、✓ 一键完成、休息计时 3:00 + +30s/跳过、进度条、动作 chips。
- 四种跟踪模式（负重/次数/计时/距离）都正确切换，不再给平板支撑显示 kg/lb。
- 完成一组后整行染绿，扫一眼知道进度。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|
| **P1** | 休息计时是组件内 state：离开训练页（切 tab / 回今日）再回来，计时**消失** | 训练中切出去看消息/查动作，回来节奏断了 | 用 `session.restEndsAt` 持久化，进入时按时间戳重算（字段已存在） |
| **P1** | "放弃"按钮与"结束训练"并排，**单击即丢弃整场，无二次确认** | 误触丢训练，且无撤销 | 二次确认，或改为"结束并保存"为主、"放弃"进"…" |
| **P1** | 顶部仍保留全局 header（练迹/日期/本地存储，70px），训练中不收起 | 800px 屏幕上 17% 被 chrome 占用 | 训练中隐藏 brand，只留返回 + 计时 |
| P2 | 每组预填上次数值，连点两次 ✓ 会静默记成 `105×6`（我实测发生） | 用户以为"确认"，实际写入了没做过的重量 | 预填值用占位样式，首次需显式编辑或长按确认；或记录后标"沿用上次" |
| P2 | "上次"列 44px，360px 宽时折成两行（`105 kg ×` / `6`） | 扫读困难 | 列宽自适应或缩写 `105×6` |
| P2 | kg/lb 切换放在每个动作面板里 | 单位是全局偏好，却被当成局部开关 | 移到设置，面板只显示当前单位 |
| P2 | 动作 chips 横向溢出，第 5 个只露一半 | 不知道还有几个动作 | 加渐隐/计数（`+2`） |

**一句话改法**：训练中只保留"这一组"和"还剩几组"，其余全部让位。

### 3.6 训练详情

**我实际体验到的**

- 汇总（工作组/容量/时长）+ 逐动作逐组 + 点组可更正 + 改日期 + 标记剩余为跳过 + 删除（墓碑可恢复）+ 分享 + 周目标关联修改。
- 能力是齐的，甚至比很多商业 App 全。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|

### 3.7 饮食

**它想解决什么**：记录实际吃了什么，知道今天摄入了多少。

**我实际体验到的**

- 四个餐次卡片 + 添加；搜索/分类/常吃（没有）；按个/按克切换（鸡蛋"2 个"很自然）；份量预览实时算 kcal/蛋白；手工填总量兜底。
- 过敏原过滤会隐藏相关食物，并提示"已隐藏 N 项"。

**问题**

| 级别 | 现象 | 影响 | 建议 |
|---|---|---|---|
| **P1** | **只能记今天**，没有日期切换 | 昨晚忘了记，第二天补不了；也无法回看上周吃了什么 | 顶部加日期切换（← 今天 →），支持补记 |
| **P1** | 目标 `2350 kcal / 165 g` 是种子数据写死的（`seed.ts:183`），**没有任何 UI 能改**，与身高体重无关 | 55kg 女用户也看到 2350；"目标"变成假数字 | 按 BMR×系数推荐 + 可手动覆盖；或明确标"参考值，可设置" |
| **P1** | 采集了 carb/fat（`addFood` 写入），但界面**只显示 kcal 与蛋白** | 数据白采；用户以为只记蛋白 | 要么展示三大宏量，要么不采集 |
| P1 | 无常吃/最近/复制上一餐 | 每天同样的早餐要重新搜 4 次 | 顶部"常吃"+"复制昨天" |
| P1 | 条目不能编辑，只能删（✕ 26×26，无撤销） | 份量填错只能删了重记 | 点条目编辑份量；删除给 3 秒撤销 |
| P2 | 份量提示重复："1块 ≈ 150g（1块约 150g）" | 像 bug | 只留一句 |
| P2 | 无周/月营养趋势 | 记录没有反馈闭环 | 教练页或饮食页加 7 天趋势 |
| P2 | README 写"常吃/文字解析"，代码里都没有 | 承诺与实现不一致 | 更新 README，或补实现 |

**一句话改法**：饮食要么做成"能坚持的记录器"（日期、常吃、编辑、趋势），要么明确降级为"快速记一笔"。

### 3.8 教练

**它想解决什么**：看见进步。

**我实际体验到的**

## 4. 六个横向问题（比单点更贵）

### 4.1 记录可信度：补录存了等于没存，1 组就算完成

**两个方向相反、根因相同的错误。**

**（1）补录：存了等于没存**

实测：补录一次训练（选 1 个动作）→ toast"补录已保存"→ 历史仍 `42 次`、累计仍 `42 次`、第一行仍是 10/24。

原因：`buildBackfill` 生成 `status: 'completed'` 的会话，但组全是 `planned`；而"有效训练"要求至少 1 个 `completed` 工作组（`metrics.ts:30`）。于是记录被历史、累计、周目标、教练**全部过滤**，只有导出 JSON 里能看到它。

这不是显示问题，是**承诺问题**：产品的第一承诺是"可靠留住每次训练"，而补录路径直接违背它，且用户拿不到任何失败信号。

**（2）完成：1/16 组就算练完**

实测：16 个计划组的训练只完成 1 组，结束面板 `1 工作组 · 1/16 完成/计划`，确认后今日页写"今天已经练完了"，周进度 `1/3`，该日变"完成"。

**为什么贵**：周目标是这个产品唯一"承诺型"的功能，也是留存的核心钩子。如果 1 组就能达标，用户会迅速学会"打卡式训练"，目标失去意义；而认真练完的用户也不会因此获得更强的成就感。

**建议**：
1. 补录要么补 1 组真实数据，要么自动走 `selfReported`（该口径本来就能被统计），并加"补录后必须出现在历史"的单测。
2. 结束面板显示"完成 12/16 组"，未达阈值（如 ≥60% 计划组或 ≥3 工作组）时默认**不计入**周目标，需手动勾选并提示"本次仅完成 X%，仍要计入吗？"
3. 今日页状态从二态（完成/未完成）改为三态：**已完成 / 部分完成 / 未开始**。
4. 周目标统计区分"达标次数"与"训练次数"（现在两个数字都有，但用户只看到前者）。

### 4.2 错过之后：最高频的真实动作没有路径

真实用户的周一：加班没练。周二想练周一的课。
当前路径：
- 训练页点"上肢 A"那行 → 提示"这项排在 10月26日，今天开始会记为加练"，**不计入周目标**。
- 想让它计入，必须：周目标 → 项目明细 → 点这一项 → 顺延到今天 → 再回训练页开始。

**建议**：点错过项时直接给二选一——
- "补做这一项（顺延到今天）" → 顺延 + 立即开始
- "只加练，不改计划" → 开始但不计入

这是**一个弹层**的工作量，能救回大量"错过一次就放弃整周"的用户。

### 4.3 数据诚实：默认值伪装成用户数据

| 位置 | 现象 |
|---|---|
| 饮食目标 | 2350 kcal / 165 g 写死，无 UI 可改 |
| 目标体重 | placeholder 75 与真实值同样式，同屏又说"还没设置" |
| 体重趋势 | 标签"近 6 周"，实际取全部 14 条（约 4 周） |
| 训练页错过日 | 只显示日期，不显示"未完成" |
| 引体向上 | `0 kg × 0` + `+6%` |

这个产品最大的差异化是"数据属于你、不骗你"。**默认值和占位符必须看起来像默认值**，否则差异化就成了反讽。

### 4.4 半成品模块：饮食与教练

- 饮食：只能记今天、目标写死、无编辑、无常吃、无趋势、宏量采集不展示。完成度约 40%。
- 教练：AI 不可用（CORS）、力量榜口径错、趋势图无信息量、4516px 长页。完成度约 50%。

用户不会按模块评分，他们按**最弱的那一环**评价整个产品。要么补齐，要么在导航上降级（把饮食做成"今日页里的一个卡片"，把 AI 收进设置）。

### 4.5 可撤销性：删除与放弃

| 操作 | 现状 | 风险 |
|---|---|---|
| 放弃训练 | 单击即丢弃，无确认 | 高（整场训练） |
| 删除饮食条目 | 单击 ✕ 即删，无撤销 | 中 |
| 删除体重 | 单击 ✕ 即删，无撤销 | 中 |
| 删除训练 | 有确认 + 墓碑恢复 | 低（做得对） |

Toast 目前不支持 action。加一个 `push(msg, { action: '撤销', onAction })` 就能覆盖饮食/体重两处；放弃训练单独加确认。

### 4.6 留存：没有回访理由

- 无本地通知/提醒（"今天该练下肢 A"）。
- 无周报推送/周结算提示。
- 有"连续达标周"，但埋在周目标卡第 3 个数字，且新用户永远是 0。
- 练完的即时反馈是有的（本次 vs 上次），但被 -92.3% 这类错误口径伤害。

健身 App 的次周留存，靠的是"到点提醒 + 上次的成就感"。前者完全没有，后者口径不稳。

## 5. 信息架构建议

### 现状：6 tab

```
今日 | 训练 | 周目标 | 饮食 | 教练 | 我的
              ↑ 与"训练→计划"重叠      ↑ AI+图表混在一起
```

### 建议：5 tab

```
今日        今天做什么、做到哪了（含周进度圆环）
训练        本周（默认）/ 模板 / 历史 / 动作库    ← 吸收"周目标"
饮食        今天 + 日期切换 + 常吃
进展        本周小结 / 力量趋势 / 目标 / AI（折叠）
我的        身体 / 设置 / 数据与备份
```

理由：
- "周目标"与"训练→计划"本就是同一件事的两个视图，合并后训练页有了明确的默认视图（本周），周目标不再需要独立 tab。
- "教练"改"进展"，名实相符；AI 变成进展里的一个可选工具，而不是一个 tab。
- 5 tab 在 360px 宽下每个可到 64px，触控和字号都能达标。
- 代价：周目标的"承诺感"会被稀释。补偿方式：今日页保留周进度圆环，训练页顶部保留"本周 1/3"。

如果不想动导航，最低成本的改法是**只改名**：周目标 → 计划，教练 → 进展，并在训练页把"计划"段的标题改成"模板"。

- 社交/排行榜/好友（与"训练是自己的事"冲突，且需要运营）
- 课程视频库（内容成本）
- 拍照识别食物（准确率不够会砸口碑）
- 自适应 TDEE（当前连基础营养目标都没让用户设，先补前者）

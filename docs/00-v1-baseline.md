## 2. 用户与价值

面向希望规律进行力量训练、兼顾中餐饮食记录、重视离线和数据可迁移的一般健康成年人。v1 不提供诊疗、康复处方及特殊健康人群的自动训练/热量方案。

核心任务：快速记下一组 → 可靠保留本次训练 → 看见历史进步；实际饮食与体重记录形成辅助反馈。AI 是可选的输入与解释工具，所有核心记录可无模型、无账号、断网完成。

目标有两类路径：初学者通过模板开始；已有习惯者自建模板或直接空白训练。无需填写身高体重即可开始记录训练；需要营养计算时再补必要字段。

## 3. v1 功能范围

下表“必做”是最终 v1 范围，实施先后由第 5 节确定，不表示 demo 已支持。

| ID | 必做功能 | 完整边界 |
|---|---|---|
| F01 | 最小首启与档案 | 可跳过非必要信息；训练经验、器械、每周安排；营养资料按需补；限制与过敏显式确认 |
| F02 | 模板和计划 | 3 套审核过的入门模板：每周 2 次全身、3 次全身、4 次上下肢；支持自建、复制、编辑；生效版本和历史快照 |
| F03 | 完整训练会话 | 开始、暂停、恢复、结束、放弃；逐组重量/次数或时长/距离；上次记录、热身/工作组、RPE 可选；本地提交、进程恢复 |
| F04 | 现场应变 | 临时加删动作、换动作、跳过组；只影响本次；休息计时；查看其他页面后返回；不自动按新动作沿用旧负荷 |
| F05 | 进步反馈 | 历史编辑、总结、有效工作组数、可比较容量、重复次数/负荷 PR、适用范围内 e1RM 趋势；首次记录为基线 |
| F06 | 真实饮食 | 手工填热量/蛋白、食物检索、最近/收藏、复制餐次、照餐单确认、可选文字解析；可改删；来源、份量与完整度可见 |
| F07 | 身体与营养目标 | 体重记录和趋势；完整资料下提供初始估计或手工目标；目标版本和采纳记录；未知实际摄入不以计划替代 |
| F08 | 周习惯与日历 | 周目标、周内顺延、无限额真实豁免、历史补录/更正、训练次数/天数分开、可重算周结果 |
| F09 | 数据自主 | 完整 JSON 导入导出、校验预览、合并去重、替换前备份、失败回滚；本地清空；明确远端及备份删除行为 |
| F10 | 可选自托管同步 | 单人多设备；显式配对、认证、离线队列、版本冲突、双方副本保留、可恢复选择；不自动 LWW |
| F11 | 可选 AI | 单会话跨训练/饮食上下文、解释数据、文字饮食草稿；端点/模型/Key 配置、超时取消、错误恢复、变更预览；不直接改目标或计划 |
| F12 | 交付品质 | Android 安装包、HTTPS PWA；空/加载/错误/恢复状态、可访问操作、更新提示、隐私说明、离线及同步状态 |

训练模板必须包含适用条件、器械、组次、休息、渐进/保持规则和内容版本，不以模板数量替代内容审核。动作库需覆盖全部模板与每个可替换动作；没有合适替代时诚实显示为空，允许手工选择。支持自定义动作，稳定 ID，动作记录模式创建后不可直接改变，有历史时通过新动作版本处理。

### 3.1 明确后置

自适应 TDEE 自动调目标、睡眠/HRV 自动调负荷、油量后台学习、拍照识别、超级组编排、自动递减组流程、动作视频/动画、BLE、健康平台接入、智能手表、小程序、iOS 上架、社交/家庭/多用户、运行时插件、云托管账号与付费结算、深色模式、多语言界面、Hevy/Strong 专属 CSV 导入。

后置不意味着不能保存普通工作组或使用中文别名；v1 不为这些能力构建额外页面和运行时框架。商业模式尚未验证，不将“买断”“唯一中餐库”作为已定宣传。

### 3.2 非功能目标

- 已提示保存成功的记录在杀进程后可恢复；失败保持输入，允许重试。
- 不以自动更新、改计划、同步、归档为由删除历史事实。
- 用户已配对时网络失败保持配对及待同步状态，不静默换成另一个数据集。
- 同一设备可有多个页面，但同一数据集最多一个未结束会话；冲突时保留事实并要求用户处理。
- 以 3 年数据集测试：600 会话、36,000 组、4,000 餐、1,100 体重记录。性能环境与阈值见验收文档。
- 不要求双击 file:// 全功能可用；本地开发和发布使用构建产物。原始 demo 仅供参考。

## 4. 产品指标与统计口径

核心观察指标：首次训练完成率、二周/四周仍有记录比例、单组记录耗时、成功保存后恢复率、全天饮食记录覆盖率、同步失败恢复率。用户内容默认不上传作为遥测；试用可自愿提供反馈，不以隐私明细换取产品指标。

训练次数是已完成有效会话数；训练天数是这些会话的不同业务日期数；周目标完成数是唯一已满足计划发生项数。三者不混用。训练与饮食没有合并的“总完成率”。

## 5. 交付阶段

| 阶段 | 交付 | 出口 |
|---|---|---|
| M0 契约 | 本文、模型、周规则、验收及内容清单 | 文档交叉检查，无未定义关键口径 |
| M1 单机训练试用 | F01–05、F08、F09 本地部分、基础 F12 | 训练、历史、周规则、保存恢复门禁通过；只称试用版 |
| M2 饮食与教练试用 | F06、F07、F11 | 手工路径离线可用，AI 不绕过校验；内容审核通过 |
| M3 正式 v1 | F10、完整 F09/F12、全量回归 | 12 号文档全部必选项通过，Android/PWA 真机证据完整 |

自托管可以不启用，但最终 v1 声明支持该能力，相关门禁不可省略。自适应算法不阻塞 v1。

## 6. 决策台账

| ID | 决策 | 原方案处理 | 原因 |
|---|---|---|---|
| D01 | demo 可推翻，采用新领域模型 | 不继承全局可变 state 和旧仓储契约 | 用户本轮明确授权 |
| D02 | Android + PWA；允许构建依赖 | 取消双击零构建与禁止原生壳的要求 | 可靠存储与工程边界优先 |
| D03 | 模板优先、AI 可选 | 取消从零模型生成作为主入口 | 可审计、可离线 |
| D04 | 周最低目标默认等于计划次数，可显式降低 | 取消 60%/80% 隐式阈值 | 用户可理解，口径确定 |
| D05 | 顺延不减目标；豁免无额度；零目标周不新增连续周 | 替代 09 号旧算法 | 保留真实情况和统计一致性 |
| D06 | 自适应 TDEE 和后台油量学习后置 | 替代 08/07 中 v1 必做要求 | 先验证真实输入质量 |
| D07 | 本地事务 + 持久化 outbox + 条件快照同步 | 不采用整份无条件 LWW | 不静默丢记录 |
| D08 | 无插件平台、无多用户 | 旧 L3 与 scope 扩展承诺撤销 | 避免未验证的隔离与维护成本 |
| D09 | 保留全部训练/饮食/体重事实 | 取消 90/180 天自动裁剪事实 | 长期趋势依赖历史 |
| D10 | 老 demo 数据经显式导入转换 | 不自动覆盖旧 key、不编造逐组与实际摄入 | 重构自由与数据诚实兼顾 |
| D11 | 自托管删除采用 v2 持久删除状态和代次隔离；商业云单独设计 | 取代旧文档允许删除后自动重传及 90 天墓碑的方案 | 防止离线旧设备复活；v2 尚未实现，不能沿用旧验收结论 |

框架具体依赖版本、内容版权材料、营养策略数值和目标设备实测结果在实现阶段提供证据；缺少这些证据的相应功能不可标记验收通过。它们不改变本版范围和业务语义。

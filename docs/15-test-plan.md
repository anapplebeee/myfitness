# v1 测试方案

版本：1.0；日期：2026-10-24；状态：**测试计划，全部待执行**。本文不改变 [12](12-v1-acceptance.md) 的验收项，只规定"怎么测、用什么夹具、什么算通过"。验收项编号以 12 为准，实施排期见 [14](14-implementation-plan.md)，追踪表见 [16](16-ac-traceability.md)。

## 1. 目标与原则

1. **业务不变量用自动化覆盖，平台行为用真机证据**：领域规则必须 D 层可重复；Android/PWA 行为必须在目标设备上留证据。
2. **每个 AC 至少一条可执行用例**：没有用例的 AC 视为未覆盖，不能用"代码已写"替代。
3. **测试先于实现**：S0 的契约测试、S2 的 W01–W16、S7 的协议契约在实现前先写。
4. **失败必须可解释**：每条失败记录输入、时钟、时区、数据版本、环境、堆栈或截图。
5. **不测未定义行为**：文档冲突时先修文档，不为歧义写测试。

## 2. 测试层级

| 层级 | 定义 | 职责 | 工具 | 运行频率 | 目标占比 |
|---|---|---|---|---|---|
| D | 确定性领域测试 | 纯函数、规则、单位、统计、结算 | Vitest（Node，无 DOM） | 每次提交 | 60% |
| C | 契约测试 | 仓储、迁移、同步协议、适配器、导入导出 | Vitest + fake-indexeddb + supertest/undici | 每次合并 | 25% |
| E | 端到端 | 关键用户旅程、离线、更新、导入导出 | Playwright（Chromium + Android Chrome） | 每晚 | 10% |
| P | 真机/安装/升级 | 安装、升级、杀进程、后台、锁屏、飞行模式 | adb 脚本 + 人工清单 | 每周 + 发布前 | 4% |
| R | 内容/人工审查 | 模板、食物许可、营养策略、隐私、对比度 | 审查清单 + 人工 | 里程碑 | 1% |

## 4. 测试数据与夹具

### 4.1 三年种子数据生成器

| 项 | 规格 |
|---|---|
| 规模 | 600 会话、36,000 组、4,000 餐（16,000 条目）、1,100 体重、审计与 tombstone |
| 分布 | 每周 3–4 练；动作 5–9 个/场；组 3–7 个/动作；含热身与跳过 |
| 时间 | 跨 3 年、跨时区（上海/纽约）、含跨午夜与 DST 边界 |
| 随机 | 固定 seed，可复现；生成脚本与校验和入库 |
| 用途 | 性能基准、快照容量、导入导出、迁移 |

### 4.2 固定场景库

- **周规则**：W01–W16 全部固定为可执行用例，输入含 goal/occurrences/sessions/now/ruleVersion。
- **冲突**：同实体双改、删改冲突、同日不同体重、同周不同目标、多活动会话、引用失效。
- **协议错误**：401/403/404/409/412/413/422/428/500/503 各一条。
- **导入**：合法、非法 JSON、schema 错、引用错、单位错、超限、同 ID 同内容、同 ID 异内容、跨数据集。
- **安全**：存储型 XSS payload（食物名、备注、导入 label、模型回复）、CSP 违规、token 泄露扫描样本。
- **可访问性**：大字体、键盘 Tab 顺序、读屏名称、减少动效。

### 4.3 时间与并发

- 注入 `Clock` 与 `IdGenerator`，禁止领域代码读真实时间（AC-A01）。
- 跨午夜（W09）、时区切换（W14）、DST、月末/年末边界。
- 双标签页、双设备、在途上传时新增写、租约过期接管。

## 6. 专项测试

| 专项 | 内容 | 层级 | 通过标准 |
|---|---|---|---|
| **本地事务与恢复** | CommitResult 四态；事务中断；配额耗尽；强杀 20 次 | C/P | 已提示保存的记录 20/20 恢复；失败不虚假成功 |
| **迁移** | v1→v2 模拟、逐版迁移、中途失败、未来 schema | C/P | 迁移后事实数量/引用一致；失败保持旧库；未来版本拒写 |
| **快照容量** | 三年数据序列化、UTF-8 字节、gzip、上传时长、内存峰值 | C/P | ≤32 MiB（或按 ADR 决策）；上传失败可恢复 |
| **同步协议** | 条件写、幂等、错误码、CORS、ETag、304、备份恢复 | C | 每个状态码有契约用例；无无条件覆盖路径 |
| **冲突** | 三方比对、ConflictCopy、预览失效、双方副本导出 | C/E | 不自动 LWW；副本可导出；预览失效需重新生成 |
| **安全** | CSP、XSS、token、日志、导出、Android 备份 | C/E/R | XSS 0 执行；导出/日志 0 命中密钥；备份不上云 |
| **可访问性** | 对比度、触控、读屏、键盘、减少动效 | E/P/R | 12:114 全部满足；axe 0 serious/critical |
| **性能** | 冷启动、录组、90 天查询、内存 | P | 12:118 阈值，≥100 次采样 |
| **离线/PWA** | 预缓存、飞行模式、更新提示、训练中不强刷 | E/P | 完成安装后飞行模式冷启动可用；训练中不切换 |
| **内容审查** | 模板、食物、Policy、许可、署名 | R | 12:103 AC-C04；无来源不发布 |

## 7. 覆盖率与质量门槛

| 指标 | 门槛 | 说明 |
|---|---|---|
| 领域纯函数语句/分支覆盖 | ≥90% | W01–W16 必须 100% |
| 仓储契约状态覆盖 | 100% | committed/validationError/storageError/conflict |
| 协议错误码覆盖 | 100% | 02:62 全部状态码 |
| 12 号 AC 覆盖 | 100% 有执行记录 | 未执行不得标通过 |
| 每 F 功能 E2E 或真机 | ≥1 条 | 无自动化则必须有人工证据 |
| 安全用例 | 0 失败 | XSS/密钥/备份为阻塞 |
| a11y | axe 0 serious/critical | 手工检查另计 |
| 缺陷 | 发布时 0 P0/P1 | 数据丢失/静默覆盖/密钥泄露/不可恢复升级/周统计不幂等一律阻塞 |

覆盖率不达标不阻塞合并到 feature 分支，但阻塞进入 G 门禁。

## 8. 缺陷分级与处理

| 级别 | 定义 | 例子 | 处理 |
|---|---|---|---|
| P0 阻塞 | 数据丢失、静默覆盖、密钥泄露、不可恢复升级、周统计不幂等 | 强杀丢失已保存组 | 立即修，阻断发布 |
| P1 严重 | 核心流程不可用、错误结果、崩溃 | 结束训练后无法恢复；PR 计算错误 | 当前迭代修 |
| P2 一般 | 次要功能异常、有绕过 | 复制餐次顺序错 | 排入下迭代 |
| P3 轻微 | 文案、样式、体验 | 间距不一致 | 收集批量修 |

每条缺陷必须引用受影响的 12 号 AC 编号（12:137）。

## 10. 证据与可追溯

### 10.1 证据格式

每条 AC 的证据包含：

- AC 编号与用例 ID（如 `T-F03-004-P`）。
- 实现版本（提交哈希 + 构建号）。
- 环境（设备型号、系统、WebView、浏览器版本）。
- 输入数据（夹具 ID 或检查和）。
- 实际结果（日志摘要、截图、录屏、性能数据）。
- 执行人/日期。
- 状态：通过/失败/阻塞/未执行。

### 10.2 目录约定

```
docs/evidence/
  W02/            # 按迭代周号，与 14 号排期一致（W01–W20）
    T-F03-001-D.md
    T-F03-004-P.mp4
  release-v1/
    perf-report.md
    device-matrix.md
```

### 10.3 状态同步

- 12 号 §11 结果表是唯一权威；测试执行后立即更新，不在迭代末集中补。
- 16 号追踪表用于快速查看覆盖情况，数据从 12 号同步。
- 任何"通过"必须有证据路径，否则视为未执行。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 夹具不稳定 | 测试结果不可信 | 固定 seed、版本化夹具、校验和 |
| 真机不足 | P 层证据缺失 | W2 前采购；模拟器只作补充 |
| AC 不可度量 | 门禁失效 | 13 号已列；G0 前改写为可判定条件 |
| 测试滞后于实现 | 返工 | 测试先写（S0/S2/S7 强制） |
| 环境差异 | 本地过、CI 挂 | 固定 Node/浏览器版本；容器化 |

## 14. 与 12 号的关系

12 号定义"验收什么、什么算通过"；本文定义"怎么测、用什么数据、证据放哪"。两者冲突时以 12 号为准；12 号未覆盖的测试方法细节由本文补充，不新增验收项。新增验收项必须先改 12 号并同步 00 的范围追踪。

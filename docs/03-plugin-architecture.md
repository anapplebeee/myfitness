# v1 模块边界与扩展策略

版本1.0；2026-10-23；待实现；范围以[00](00-v1-baseline.md)为准。旧插件方案见归档，已撤销L3/Registry/Hook总线必做要求。

## 1. v1的扩展方式

使用编译期显式模块和依赖注入，不运行远程代码，不建设插件市场。数据包和基础设施端口是两类扩展，不能混为权限隔离。

| 边界 | v1职责 | 明确不承诺 |
|---|---|---|
| LocalRepository | 事务、查询、快照导出；默认IndexedDB | 任意数据库无成本替换 |
| ModelProvider | 请求、流式响应、能力差异、超时取消 | 任意OpenAI兼容服务必定支持全部参数 |
| PlatformServices | 前后台、常亮、返回键、文件导出与密钥存储 | BLE/健康平台 |
| SyncTransport | 02定义的认证、条件写、幂等请求 | LWW和任意第三方对象存储 |
| ContentPackage | 动作/食物/模板的版本、许可、校验和 | 运行时执行脚本 |

领域规则不认识适配库；应用服务经端口调用；界面不能绕过事务。替换适配器需通过同一契约测试，失败必须可观察，不以吞异常作为隔离。

## 2. 数据包

每包记录packageId/version/licenseRef/attribution/checksum，导入验证schema与引用。用户历史保存必要内容快照，更新食物库不重算已确认摄入，更新动作提示不改旧组记录。数据包更新失败继续旧完整版本。

无来源或商业再分发权未核实的数据包不得随正式版发布；软件代码许可不自动证明数据许可。

## 3. 后续扩展

多用户、家庭、分享、设备接入另立设计与威胁模型，不能用前端scope或十行身份接口声称具备服务端隔离。v1只保留datasetId与稳定实体ID，不引入角色、分享token、事件钩子或无实际消费者的注册表。

验收关联：AC-A01/A02、AC-C04、AC-P04、AC-S01–S09。跨模块变更必须同步02/11和对应验收，不能由扩展模块自行改迁移链。

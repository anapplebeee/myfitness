# 商业云后端 MVP：实施说明与差距清单

日期：2026-10-29；状态：**内测实现，未通过发布门禁**。设计基线见 [28](28-commercial-backend-mvp.md)。

本文回答三件事：按设计实现了什么、哪里有偏离、还差什么才能对外。不承诺任何未通过验证的能力。

## 2. 与设计逐条对账

### 2.1 接口（28 §4.2）

| 设计接口 | 实现 | 说明 |
|---|---|---|
| `POST /auth/code` | ✅ | 已注册与未注册同一响应；邮箱级限流超限仍回 202（不泄露"该邮箱刚被请求过"），IP 级超限回 429 |
| `POST /auth/verify` | ✅ | 验证码绑定用途；非登录用途签发近期验证令牌 |
| `POST /auth/refresh` / `logout` | ✅ | 轮换 + 重放检测；注销即撤销当前会话 |
| `GET /devices` / `DELETE /devices/{id}` | ✅ | 他人设备 404 |
| `GET /dataset` | ✅ | 三态；`active` 返回快照与强 ETag；`deleted` 不返回任何快照字段 |
| `PUT /dataset` | ✅ | `If-None-Match: *` / `If-Match`；幂等键必填；epoch 可选校验；412/409/413/422/428 分类齐全 |
| `GET /dataset/versions` / `{id}` | ✅ | 30 天、最多 10 个、去重同哈希、他人 404 |
| `POST /dataset/replace` | ✅ | 换 `datasetId` + 推进 `epoch` + 旧数据进历史；响应带 `previousDatasetId` |
| `POST /dataset/reinitialize` | ✅ | 仅 `deleted`；`If-Match` 用删除代次令牌；`DELETION_TOKEN_STALE` 412 |
| `DELETE /dataset` | ✅ | 近期验证 + 当前 ETag + 幂等键；同步删除快照与历史版本 |
| `DELETE /account` | ✅ | 近期验证 + 状态凭证；撤销全部会话；状态查询凭摘要 |
| `GET /account/deletion` | ✅（新增） | 设计只要求"可查询"，未定路径；这里定为无登录 + `X-Status-Token`，不进 URL |

返回分类与设计一致：401/403/404/409/412/413/422/428/429/5xx。错误体只有 `code`、`message`、`requestId`。

### 2.2 写入顺序（28 §4.2）

实现顺序与设计逐项一致，唯一值得写下来的是**为什么幂等必须先于条件**：

> 一次成功的 `PUT` 会把 `revision` 推进 1。客户端在收到响应前断网、重试时，
> 手里的 `If-Match` 必然过期。若先查条件，重试永远 412——
> 客户端要么放弃（丢同步），要么绕过条件（静默覆盖）。两种结果都不能接受。

### 2.3 快照校验（28 §4.1）

| 规则 | 实现 |
|---|---|
| `schemaVersion` / `ruleVersion` / `canonicalizationVersion` 白名单 | ✅ 不在白名单 → 422 `VERSION_UNSUPPORTED`，不降级、不清空 |
| 规范化（键序、数组原序、`undefined` 省略、`null` 保留、无空白） | ✅ `server/domain/canonical.mjs`，与客户端 `transfer.ts` 同规则 |
| 服务端独立重算 SHA-256 | ✅ 客户端提交的 `snapshotHash` 只作交叉校验，不采信 |
| 未压缩 64 MiB 上限 | ✅ 默认值即 64 MiB，按规范化 UTF-8 字节计 |
| `datasetId` 归属 | ✅ 普通写入必须与当前一致（否则 422）；初始化/替换/重新启用由服务端指派并写回快照 |

**未做**：字段清单冻结。服务端只校验顶层类型与数组字段，不逐字段解释语义。原因：客户端
`snapshot.ts` 仍在演进（饮水和提醒是最近才补进快照的），此时冻结清单会立刻过期。
代价是服务端无法发现"字段名拼错但结构合法"的快照——这类问题只能在客户端导出→云→新机
逐字段比对（CB-A15）时暴露。

### 2.4 认证与安全（28 §5.3）

| 要求 | 实现 |
|---|---|
| 6 位安全随机、10 分钟、单次、5 次错误 | ✅ |
| 只存带密钥摘要，不存无密钥哈希 | ✅ HMAC-SHA256(`challengeId:code`) |
| 验证码不进 URL / 日志 / 审计 / 响应 | ✅ 测试断言审计中无 `@`、无验证码 |
| 访问 15 分钟 / 刷新 30 天 + 轮换 + 重放检测 | ✅ 重放即撤销整条会话 |
| 受保护请求逐次检查会话状态 | ✅ 不等令牌过期 |
| 清空/注销需独立近期验证，绑定用途、单次 | ✅ 用途不匹配 403 |
| 客户端提交的 accountId 不作授权依据 | ✅ 测试验证伪造无效 |

**未做**：PWA 会话方案（威胁评审）、CSP、CSRF 防护。当前假设同源部署且客户端未接入。

## 3. 存储实现

| 层 | 实现 | 理由 |
|---|---|---|
| 端口 | `read` / `transaction(keys, fn)` / `close` | 三个动作足够表达"读一致视图"与"串行提交" |
| 内存 | 克隆—执行—提交 | 测试用 |
| 文件 | 临时文件 → fsync → rename → fsync 目录；台账同文件 | 一次原子写同时落地"当前快照 + 历史版本 + revision + 幂等回执 + 删除台账"，这正是设计要求的同事务语义 |
| 并发 | 进程内 keyed lock（按账号 + 数据集） | 同一账号两次条件写绝不能并行，否则两边都判定条件成立 |
| 故障 | 解析失败 / 台账断链 → **拒绝启动** | 以空库启动会让"已删除"的数据被旧设备写回来 |

PostgreSQL 结构在 `server/store/schema.sql`，**未执行**（本机无数据库）。
换 PG 时需要补两件文件存储做不到的事：`pg_advisory_xact_lock` 串行化、台账跨故障域同步复制。

### 4.1 测试抓出的两个真实缺陷

1. **暴力破解计数被事务回滚吞掉**：原实现校验失败时 `throw`，事务整体回滚，
   `attempts` 永远回到 0 —— 5 次上限等于不存在。改为"返回失败码 + 显式 persist"，
   在事务外抛错。
2. **刷新令牌重放不撤销会话**：重放分支里先 `revokeSession` 再 `throw`，撤销随回滚消失，
   泄露的刷新令牌可以无限续期。同样改为提交后再抛。

这两个都不是笔误，而是"用异常表达业务结果"带来的系统性坑：任何需要在失败时保留副作用的
逻辑，都不能靠抛异常。

## 5. 距发布还差什么

| 项 | 影响 | 建议 |
|---|---|---|
| 存储换 PostgreSQL | 单实例、无水平扩展、大快照克隆开销未测 | 先做 PG 适配器 + 契约测试全绿，再压测 CB-A16 |
| 台账跨故障域复制 + 独立归档 | CB-A17/A23 不过，删除承诺不成立 | 托管 PG 同步备库 + 只读归档，恢复演练 |
| 字段清单冻结 | CB-A15 无法验收 | 与客户端 `snapshot.ts` 同步出一份机器可读清单，导入/导出/云三方比对 |
| 客户端接入 | 用户完全用不到 | 登录、授权开启、绑定预览、同步状态、冲突合并五屏 |
| 邮件与限流压测 | 生产发信质量未知 | 选服务商后压测并监控投递率 |
| CORS / PWA 会话 / CSRF | 跨域部署不可用 | 威胁评审后定方案 |
| 运维：监控、告警、值班、回滚 | CB-A20 不过 | 与部署方案一起定 |

**结论**：当前实现可以作为内测后端使用（单机、少量用户、可接受重建数据），
不能作为公开付费版本的云端，也不应对用户宣传"已支持云备份"。

# ADR-0004：自托管同步协议的版本化与删除防复活

- 状态：设计决议，待实施及验收；2026-10-28。
- 规范性协议：[单人自托管同步契约 v2](../sync-contract.md)。商业云使用独立协议，见 [28](../28-commercial-backend-mvp.md)。

## 背景

原 v1 文档之间对删除后自动重传、90 天墓碑、是否保留删除备份、错误码、ETag、规范化及幂等校验顺序的描述不同。当前 v1 客户端和历史测试不构成防复活的服务端保证。不能通过改文字声称代码已经符合。

## 决议

采用不兼容的自托管 apiVersion=2。旧客户端必须拒绝 v2，v2 服务必须拒绝缺少实例和代次的旧写入。服务以持久化实例 ID 和代次区分全新、有效与已删除状态；清远端后删除服务管理的快照和历史备份、永久保留最小删除状态，普通上传不能复活，只有显式重新初始化可产生新代次。运营者恢复或重建服务时必须重置实例身份并复核删除状态。具体端点、响应码、条件、校验顺序、回执和恢复条件仅由 [同步契约](../sync-contract.md) 定义，避免重复口径。

规范化、数据集绑定、ETag 和错误码也以同步契约为准；原 ADR 中的 NFC 转换、统一 RPE 小数、强制导出校验 SHA-256、`422 DATASET_ID_MISMATCH`、限期 90 天墓碑及 `rev-...` ETag 均不再是权威规定。既有导出校验与同步哈希是不同版本和用途，不能直接替换旧用户文件的校验算法。自托管的规范化具体实现和跨平台测试向量须在开发前冻结；商业云单独完成其版本化规范。

## 影响与验收

- 需要迁移服务和客户端，保留旧数据并明确重新配对；不承诺 v1 和 v2 互通。
- 自托管发布以 [AC-S01–S09](../12-v1-acceptance.md) 为门禁，特别验证删除、响应丢失和旧设备隔离；既有历史证据不自动通过新要求。
- 唯一实例数据及墓碑被删除、恢复或被旧副本覆盖时，仅靠服务无法还原删除历史；必须停止同步并通过人工确认和新实例身份恢复。用户另存的本地/外部备份不能远程删除。

## 1. 旧版 UI 的问题（先认错，再改）

| # | 问题 | 具体表现 | 后果 |
|---|---|---|---|
| 1 | **同质化** | 所有区块都是「白底 + 16px 圆角 + 细边框 + 浅阴影」 | 没有主次，眼睛不知道先看哪 |
| 2 | **没有锚点** | 字号只用了 12/14/16/17 四档，最大 34px 仅出现在体重 | 一屏之内没有视觉重心 |
| 3 | **信息平铺** | 今日页把连续天数、完成率、训练数、7 天完成率并排堆 | 关键动作（打卡）被埋在下半屏 |
| 4 | **导航冗余** | 5 个 tab + 顶部 streak chip + 齿轮 | 首屏可用高度被吃掉约 130px |
| 5 | **动作库太弱** | 手绘肌群小人 + 三行文字标签 | 看不出动作长什么样，专业感为负 |
| 6 | **AI 输出是"聊天"** | 分析结果全塞进气泡纯文本 | 结构化建议被压成一大段，扫读成本高 |

## 2. 设计原则

1. **一屏一个主角**：每个页面上只有一处「大数字 / 大标题」，其余全部降级为辅助信息。
2. **深色块承担分量**：用深色卡承载"今天最重要的事"，浅色区域只放可扫读的清单。避免整页都是白卡。
3. **数字有单位、有变化方向**：任何数字旁边必须有单位与趋势（`74.2 kg ↓0.6`），不做孤零零的数值展示。

## 3. 设计语言：铁片（Plate）

命名取自杠铃片：深色铁、亮色标识、一切以刻度为准。

### 3.1 色彩

| Token | 值 | 用途 | 约束 |
|---|---|---|---|
| `--ink-950` | `#0A100D` | 深色 hero、主按钮文字底 | 只做背景，不做文字 |
| `--ink-900` | `#101915` | 深色卡的第二层 | — |
| `--paper` | `#F5F6F3` | 页面底色 | 全局唯一底色 |
| `--card` | `#FFFFFF` | 普通卡片 | — |
| `--line` | `#E4E8E2` | 分割线、卡片边框 | 1px，不用阴影替代 |
| `--text-1` | `#0F1A15` | 主文本 | — |
| `--text-2` | `#5F6F67` | 次文本 | — |
| `--text-3` | `#97A39B` | 辅助/单位 | — |
| `--brand` | `#0E7A63` | 进度、选中态、图表主线 | 不用于大面积填充 |
| `--signal` | `#C9F24D` | **仅深色底上的强调**（CTA、关键数字、进度条） | **禁止用在浅色底**（对比不足） |
| `--warn` | `#FF6B35` | 未完成、超量警示 | 一屏最多出现一处 |

对比度自检：`#C9F24D` on `#0A100D` ≈ 14:1；`#0F1A15` on `#F5F6F3` ≈ 15:1；`--text-3` 只用于 11px 以上的辅助标签，不用于正文。

### 3.2 字号与字重

| 层级 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| Display | 40 / 44 | 500 | 体重、打卡天数等唯一大数 |
| H1 | 22 / 30 | 500 | 页面主标题（"今天练什么"） |
| H2 | 16 / 24 | 500 | 卡片标题 |
| Body | 14 / 22 | 400 | 正文、列表主行 |
| Caption | 12 / 18 | 400 | 说明、单位、时间 |
| Micro | 11 / 16 | 400 | 标签、角标（仅限 ≥11px） |

规则：数字统一 `font-variant-numeric: tabular-nums`；中文不用 600/700（笔画糊），用 500 提权。

### 3.3 间距与形状

- 间距基数 4：`4 / 8 / 12 / 16 / 20 / 24 / 32`
- 页面左右留白 **16**；卡片内 padding **16**；卡片之间 **12**
- 圆角：外壳卡 `20`，内层卡 `14`，按钮 `14`，胶囊/标签 `999`
- 阴影：**只有吸底 CTA 和弹层**允许用（`0 6px 20px -8px rgba(10,16,13,.35)`），其余靠 1px 边框分层
- 触控区最小 `44×44`

## 4. 信息架构：5 tab → 4 tab

```
旧：今日 · 计划 · 教练 · 动作库 · 身体
新：今日 · 训练 · 教练 · 我的

今日（仪表盘：两个日常循环的汇合点）
├─ 快捷条  [训练 2/4 →]  [饮食 2,082 kcal →]      ← 两个主循环的一步入口
├─ 深色 hero  今天练什么 / 连续天数（点 → 打卡日历）
├─ 时间轴：训练卡（点 → 训练页）· 饮食卡（点 → 饮食计划）· 自定义条目
└─ 吸底 CTA：完成今日打卡

训练
├─ 周柱（点某天 → 切换当日清单）
├─ 计划卡（点 → 训练计划详情）
├─ 分段：本周 / 动作库 / 记录
│   ├─ 动作库卡片（点 → 动作详情）
│   └─ 记录行（点 → 该次训练明细）
└─ 吸底主按钮：开始训练（已有进行中会话时显示「继续 12:34」）
     └─ 训练进行中（全屏现场：计时 + 动作演示 + 组录入）
          ├─ 完成一组 → 组间休息（状态内切换，不是新页面）
          └─ 结束训练 → 训练总结 → 保存并打卡

教练（单身份、单会话，训练与饮食共享上下文）
├─ 上下文条（模型看到了哪些数据 → 详情）
├─ 对话（正式建议用三段式卡；闲聊用气泡）
│   ├─ 卡内「写进今天饮食」（→ 写入 + 跳今日）
│   └─ 卡内「调整计划」（→ 计划详情）
└─ 一键体检（→ 跨域三段式卡）

我的
├─ 身体（体重趋势 / 指标网格）
├─ 打卡日历
├─ 设备（心率带 / 体重秤 / 健康数据导入）
├─ 目标与偏好
└─ 设置（模型 / 数据源 / 备份 / 清空）
```

### 4.1 入口矩阵（每个功能只有一个主入口，允许一个次入口）

| 功能 / 页面 | 主入口 | 次入口 | 层级 | 返回落点 |
|---|---|---|---|---|
| 今日仪表盘 | tab 1 | — | L1 | — |
| 训练页 | tab 2 · 今日快捷条「训练」 | 今日时间轴训练卡 | L1 | 回 tab 2 |
| **训练计划详情** | 训练页计划卡 | 训练页计划卡「⋯」 | L2 | 回训练页，滚动位置保留 |
| 动作库 | 训练页分段「动作库」 | 计划详情/今日清单里的动作名 | L2 | 回训练页 |
| 动作详情 | 动作库卡片 | 计划详情动作行 · 今日清单动作名 | L3 | 回上一页 |
| 记录 / 训练明细 | 训练页分段「记录」 | — | L2 | 回训练页 |
| **训练进行中（现场）** | 训练页吸底「开始训练」 | 今日训练卡「开始」 | L2（全屏覆盖） | 二次确认后回训练页 |
| 组间休息 | 完成一组后自动 | — | 状态（非页面） | 倒计时结束自动回录入 |
| 训练总结 | 结束训练 | — | L3 | 保存后回训练页 |
| **饮食计划** | 今日快捷条「饮食」 | 今日时间轴饮食卡 · 教练建议卡「查看餐单」 | L2 | 回今日 |
| **打卡日历** | 我的 → 打卡日历 | 今日 hero 的连续天数 pill | L2 | 回上一 tab |
| 单日打卡明细 | 日历点某天 | 我的 → 打卡日历 → 某天 | L3 | 回日历 |
| **设备与心率** | 我的 → 设备 | 训练中浮层点击 → 同一页 | L2 | 回我的 |
| 身体（体重趋势） | 我的 → 身体 | 今日 hero 体重 pill | L2 | 回我的 |
| 设置 | 我的 → 设置 | — | L2 | 回我的 |

### 4.2 导航规则

1. **不再增加第 5 个 tab**。饮食、日历、设备都是高频但非"每屏都要看"的功能，用 L2 承接；一旦加 tab，每个新功能都会要求自己的位置。
2. **tab 各自记忆滚动位置与内部层级**：从「训练 → 动作库」切到「今日」再切回，应回到动作库而不是重置到本周。
3. **返回键顺序**（Android 实体键 / iOS 手势）：关弹层 → 退 L3 → 退 L2 → 回今日 tab → 再次返回才退出 App。
4. **深链允许但只到 L2**：例如分享出去的"某天打卡"直接落在日历并高亮该天；L3 页面不进深链（依赖上下文，单开无意义）。

顶部栏只保留「页面标题 + 一个动作」，**streak 移入今日页深色 hero**，把首屏让给内容。

## 5. 页面规格

### 5.1 今日（Today）— 见例图一

```
[ 训练 2/4 → ]  [ 饮食 2,082 kcal → ]        ← 快捷条（34px，轻量）
┌─ 深色 hero（--ink-950，r20）──────────────┐
│ 10月22日 周四            第3周 · 减脂期    │
│ 今天练                                    │
│ 推 · 胸肩三头            （H1 22px）       │
│ 4 个动作 · 预计 52 分钟                    │
│ ┌──────┬──────┬──────┐                   │
│ │连续   │本周   │体重   │  三枚 dark pill │
│ │12 天  │3/4   │74.2 ↓ │                 │
│ └──────┴──────┴──────┘                   │
└───────────────────────────────────────────┘
时间轴（07:30 早餐 / 18:30 训练 / 20:00 晚餐）
  · 训练卡片默认展开：每个动作一行（名称 · 组次 · 完成环）
  · 饮食卡片折叠为一行摘要，点开看明细
┌─ 吸底 ────────────────────────────────────┐
│ [ 完成今日打卡 ]  （--signal 底 + 深字）   │
└───────────────────────────────────────────┘
```

- hero 的第三个 pill（体重）点击进「我的 → 身体」；「连续天数」pill 点击进打卡日历
- **快捷条是两个主循环的一步入口**：左进训练页、右进饮食计划。这是本次 IA 修订新增的组件——避免饮食只能从时间轴二次进入
- 训练卡片里动作行左滑 → 跳过并记一笔；长按 → 调整组次
- 全部勾完自动打卡（hero 的"连续"数字即时 +1 并有一次 200ms 的放大）
- 「一句话汇报」收进右上角图标，不再占一整块区域
- **英雄区指标按周口径**（见 `docs/09-checkin-model.md`）：主位「本周 3/4 达标」、副位「连续 5 周」；「累计训练 87 天」移到「我的」
- 吸底 CTA 文案由「完成今日打卡」改为「**记录今天**」——打卡不再是动作，而是结算结果
- **完成率拆成两个指标**（不再出现混合的"完成 x/y 项"）：
  - 训练依从率 = 已完成**组数** / 计划组数（不是动作数，也不是条目数）
  - 饮食依从率 = **已记录实际**的天数 / 总天数
  两个数字分别出现在英雄区 pill 与打卡卡上，分母各自独立
- **饮食卡带"实际"层**：卡面直接显示 `计划 620 · 实际 580`；未记录时显示 `未记录（按计划估算）` 并置灰，点击进入记录（§5.14）

### 5.2 训练（Train）— 见例图二

- **周条**：7 列，每列「日 + 训练量竖条（按总组数映射高度）+ 今日高亮环」；点击切换当天
- **计划卡**：计划名 + 分化 chips（推/拉/腿/上肢）+「导入日程」次级按钮
- **动作清单**：`01 杠铃卧推  4×6-8  完成 2/4` + 右侧环形进度；点击进动作详情；右侧 chevron 进入该动作的历史记录
- 浮动按钮「+ 记录一组」→ 底部步进器（重量 2.5 步进 / 次数 / RPE 可选）
- 动作库作为二级页：**2 列网格卡**，卡面 = 动作示意（渐变占位）+ 动作名 + 肌群色点 + 难度三点

### 5.4 教练（Coach）— 见例图九（v2，单身份单会话）

> **修订**：取消「健身教练 / 营养师」双身份切换。一个人、一条会话、一份共享上下文。

**为什么合并**

| 双身份 | 单会话 |
|---|---|
| 用户要先判断"这该问谁" | 直接问，模型自己判断涉及哪域 |
| 训练与饮食的因果关系被切断（掉秤 + 掉力量必须一起看） | 同一上下文里能同时引用体重、力量、餐单 |
| 两套历史、两倍存储、两倍提示词维护 | 一条线程，一份历史 |
| 切换器常驻顶部，占掉首屏 | 顶部让给"模型看到了什么" |

**页面结构**

- 顶部：标题「教练」+ 右侧模型状态点（绿=已连 / 灰=本地）+ 齿轮
- **上下文条**（新增，替代原来的身份切换器）：一行浅底 pill，显示模型当前能看到的范围，如
  `看到：12 天打卡 · 4 次训练 · 3 周体重` → 右侧「详情」展开具体字段
  这一条是这页最该有的东西：让用户知道模型凭什么这么回答，也顺手告知"数据不足时它会说不知道"
- **AI 回复不用纯气泡**，改为三段式卡片：
  `结论`（16px 一句）→ `依据`（带数字的 2–3 条）→ `下一步`（1–2 条可执行，每条带一个按钮）
  纯闲聊才用气泡，避免"每句话都变卡片"的噪音
- 卡片底部动作按内容动态给，不写死：训练类给「调整计划」，饮食类给「写进今天饮食」，两者都涉及时给两个
- 快捷 chips 固定在输入框上方一行（可横滑）：`一键体检` `这周怎么调` `20 分钟练什么` `外食怎么点`
- 输入框吸底，发送键无内容时降级为灰

**上下文与输出契约**

| 项 | 规格 |
|---|---|
| 会话 | 单线程，`chat: Message[]`，上限 60 条（原为两线程各 40） |
| 每轮注入 | 身体档案 + 目标热量/宏量 + 近 7 天完成率 + 连签 + 最近体重趋势 + 今日日程摘要 + 最近 3 次训练的主项重量 |
| 体检输出 | 一份跨域体检：`1) 体重走向与摄入是否自洽 2) 力量/容量是否支持当前目标 3) 两周内只改 1–2 件事` |
| 输出格式 | 严格 JSON：`{ conclusion, evidence[], actions[{label, kind, payload}], plain? }`；`plain` 存在时按气泡渲染，否则按三段式卡 |
| 无数据时 | 必须显式说"数据不足，先记录 3 天体重"，不允许编造趋势 |

### 5.5 我的（Me）

```
┌ 身体 ────────────────────────────┐
│ 74.2 kg   ↓0.6 / 7天    BMI 24.2 │  ← Display 40
```

### 5.9 设备与心率（稿八）

入口：我的 → 设备（主）/ 训练中心率浮层点击（次，落在同一页）。**不在 tab 栏出现**——设备是配置性功能，不是日常页面。

**页面结构**

- 已连接设备用深色卡（实时心率是"当下最重要的事"）：设备名 + 连接点 + 电量 + **34 号实时心率** + 近 60 秒曲线 + 断开/设为默认
- 未连接设备用白卡：上次同步时间 + 上次数值 + 连接按钮
- 协议说明卡（浅绿）：明确写出"手环/手表不开放标准协议"，并给出替代路径（健康数据导入）。**这张卡是这个页面最重要的组件**——不写清楚，用户会以为是 App 坏了
- 附近设备列表：名称 + 信号强度 + 右侧状态

**训练中的心率浮层**：训练页顶部出现一条 28px 高的胶囊（心率 + 区间色点），点击展开 60 秒曲线。心率超过阈值（如 >85% HRmax）时胶囊底色转 `--warn`，并只提示一次。

**协议现实（决定这个功能能做到什么程度）**

| 设备类型 | 能否直连 | 依据 | 建议路线 |
|---|---|---|---|
| 标准心率带（Polar H10 / Garmin HRM / Wahoo TICKR） | ✅ | 标准 GATT：心率服务 `0x180D` + 测量特征 `0x2A37`（Notify），电量 `0x180F/0x2A19` | BLE 直连，首选 |
| 标准体重秤 | ⚠️ | 标准 `0x181D` 存在但消费级少见 | 能连就连，连不上走导入 |
| 小米 / 华为体脂秤 | ❌（多数） | 私有协议，需厂商 SDK | 健康数据导入 / 手动录入 |
| 小米 / 华为手环手表 | ❌ | 不开放标准 GATT 实时心率，需厂商健康平台授权 | 健康数据导入（华为运动健康 / Apple 健康） |
| Apple Watch | ❌ | 无开放 GATT；HealthKit 仅本机授权读取 | iOS 原生桥或导出 |

**降级原则**：任何设备功能失败都必须回到"手动录入可用"，不允许出现"没连上就记不了体重/心率"的阻断式设计。

### 5.13 动作素材策略（v1 不做，留位）

**决策（2026-10-23）：v1 不引入任何动作图 / 动画 / 视频，后期接开源素材包。**

理由：素材不是这个产品的差异化，但选错素材的成本很高——

| 方案 | 问题 |
|---|---|
| 手绘占位动画 | **错误动作示意图比没有更糟**：会教错动作，且用户分不清"示意"与"教学" |
| GIF（Gym visual） | 版权需付费授权，上架前还得换一次 |
| 3 帧 SVG（workout-guide） | 许可干净（CC BY-SA 4.0），但需要做 44 个动作的命名映射与署名页，是纯粹的接入工作，对核心体验无增益 |

**v1 用文字承担"怎么做"**：动作卡上给「模式图标 + 主要肌群 + 组次」，点开进动作详情看分步要点、呼吸、常见错误。**文字在准确性上优于劣质示意。**

**留位设计（关键）**

```ts
interface ExerciseMedia {
  kind: "none" | "frames" | "video"
  frames?: string[]
  poster?: string
  credit?: { name: string; license: string; url: string }
}
// v1：全部 kind = "none"，UI 走 no-media 分支
```

- 数据驱动：`media.kind` 为 `none` 时渲染紧凑动作卡；有素材时同一位置渲染播放器，**组件不变、布局自适应**
- `credit` 字段现在就留，避免后期接包时补署名补得到处都是
- 素材包与 v1 **并行不阻塞**：后期只需加数据文件 + 填 `kind`，不改任何视图代码

### 5.14 饮食实际记录（P0-1）

入口：饮食卡「记录实际」/ 饮食计划页每餐的「实际」按钮。

**三档入口，都不许打字超过一行**

| 档位 | 操作 | 产出 |
|---|---|---|
| 照计划吃 | 一键 | `actual = planned`，`confidence: 'exact'` |
| 一行字 | 一句描述（"外卖黄焖鸡"） | 模型估 `{kcal, protein}`，`confidence: 'estimate'` |

餐次卡的三种状态：

```
[ 已记录 580 kcal · 蛋白 41 g ]        实色边框
[ 照计划吃 · 620 kcal ]                浅底，等于计划
[ 未记录 · 按计划估算 ]                置灰 + 虚线边
```

分析口径：有 `actual` 用 `actual`；没有则回落 `planned`，并在所有结论后标注「按计划估算」，不允许把估算值当实测讲。

### 5.16 PR 与力量曲线（P0-2）

**PR 判定**：完成一组即算，满足任一条件

- 同动作、同重量下次数 > 历史最高

**提示**：顶部滑入一条 `--signal` 横幅，2.4 秒后自动收起，不阻断录入


**保护规则**（防止 PR 变廉价）：单组动作不出 PR；重量差 >50% 视为不同动作；每周最多提示 3 次，超出改为总结里汇总。

## 7. 交互与动效

| 场景 | 规格 |
|---|---|
| 勾选完成 | 复选框 180ms 缩放 + 环描边动画；整行文字转 `--text-3` |
| 打卡成功 | hero 数字 count-up 200ms，`--signal` 闪一次 120ms |
| 页面切换 | 底部 tab 内容 160ms 淡入 + 上移 8px；**不使用左右滑屏**（会与返回手势冲突） |
| 日历切月 | 唯一允许左右滑的地方，160ms 横移；纵向仍走整页滚动 |
| 心率超阈值 | 训练浮层胶囊转 `--warn` 并**只提示一次**，不重复弹窗（运动中打扰成本极高） |
| 休息结束 | 轻震动 + 一声短提示（原生）；Web 端只做视觉闪烁，不依赖音频权限 |
| 完成一组 | 录入区 120ms 上滑淡出 → 休息态淡入；不整页跳转 |
| 加载 | 骨架屏（形状占位），不用转圈 |
| 空态 | 一句话 + 一个主按钮，不留空白大图 |
| 错误 | 就地提示条（`--warn` 左边框），不用 alert |
| 原生 | 返回键：先关弹层 → 回今日 tab → 再退出；训练中屏幕常亮 |

## 8. 深色模式

同一套 token 反转：`--paper #0A100D`、`--card #121A16`、`--line #1F2A24`、`--text-1 #ECF1ED`；`--signal` 在深色下继续用于强调，`--brand` 提亮到 `#1FA383`。hero 卡在深色下改为比页面**更亮**的一档（`#161F1A`），保持层次。

## 9. 无障碍与性能预算

- 正文对比度 ≥ 4.5:1，大字号 ≥ 3:1（已按 §3.1 取值核算）
- 所有图标按钮带 `aria-label`；勾选状态用 `aria-checked`
- 首屏 CSS ≤ 18 KB、JS ≤ 90 KB（gzip 前），字体只用系统栈（不加载 webfont）
- 动效遵循 `prefers-reduced-motion`

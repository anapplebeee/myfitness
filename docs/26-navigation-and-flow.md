# 页面流转与导航设计

最后更新：2026-10-26
适用范围：`src/App.vue`、`src/views/**`、`src/composables/useNavigation.ts`、`useOverlay.ts`、`useBackLayer.ts`

---

## 1. 模型：两层，不是一层

应用**没有路由表**，只有两层结构：

```
第一层：标签（Tab）        ← 平级，互相切换不产生"上下级"
  今日 / 训练 / 周目标 / 饮食 / 教练 / 我的

第二层：全屏浮层（Overlay） ← 从某个标签"深入"进去
  训练详情 / 录制中 / 模板编辑 / 数据管理
```

为什么不用路由表：这是单机 PWA + Android 壳，页面数量固定，
引入 vue-router 会增加一层"URL ↔ 状态"映射，而真正需要维护的是
**返回栈**和**跳转意图**，不是路径匹配。

---

## 2. 五条原则

### 原则一：标签是"目的地"，不是"流程的一步"

底部标签栏做的是**平级切换**，不记录上下级关系。
用户在任何标签点任何标签，都是"去另一个地方"，不是"往下走"。

因此：**标签切换不记来源**。切过去就切过去了。

### 原则二：浮层是"深入"，必须能原路返回

浮层（训练详情、录制、模板编辑）从某个标签打开，
关闭后**必须回到打开它的那个标签，且该标签的状态不丢**。

实现方式：浮层是覆盖层，底层标签组件不卸载、`route` 不变。
这是最省事也最不容易错的方案——不需要"记住从哪来"，
因为"来的地方"根本没离开过。

### 原则三：跨标签跳转必须带意图

从 A 标签跳到 B 标签，如果只是 `route = B`，
用户会落到 B 的**默认首屏**，而不是他想要的那个位置。

反例（已修）：
> 今日页 →「最近训练 · 全部」→ 训练页，落在「计划」段。
> 用户点的是"全部"，想看的是历史列表，还得自己再点一次「历史」。

正例：
```ts
emit('navigate', { to: 'train', from: 'today', focus: { kind: 'history' } })
```
目的地挂载时取走意图，直接把初始状态设成"历史段"。

### 原则四：带意图的跳转要能回到来源

跨标签跳转后，目的地的返回键（系统返回键 / 边缘滑动 / 浏览器后退）
优先回到来源标签，而不是一路退到应用外。

- 今日 →「全部」→ 训练：在训练页按返回 → 回到今日
- 用户随后**主动**点了底部标签 → 来源记录作废（他自己走了，不需要送回）

### 原则五：一个动作一个入口，不制造二次点击

按钮的字面承诺必须一次达成：

| 按钮 | 承诺 | 实现 |
|---|---|---|
| 开始训练 | 开始 | 直接建会话并进录制页，不先进列表 |
| 继续训练 | 继续 | 直接回到进行中的会话 |
| 全部 | 看全部历史 | 落到训练页历史段 |
| 记录（饮食） | 记录 | 直接打开饮食记录面板 |

## 4. 完整流转表

### 4.1 从「今日」出发

| 动作 | 目的地 | 带意图 | 返回落到 |
|---|---|---|---|
| 开始训练 / 继续训练 | 录制浮层 | — | 今日 |
| 点某场最近训练 | 训练详情浮层 | — | 今日 |
| 「最近训练 · 全部」 | 训练标签 | `focus: history` | 今日 |
| 「本周节奏」 | 周目标标签 | `from: today` | 今日 |
| 「看本周安排」（顺延时） | 周目标标签 | `from: today` | 今日 |
| 饮食「记录」 | 饮食标签 | `from: today` | 今日 |

### 4.2 从「训练」出发

| 动作 | 目的地 | 带意图 | 返回落到 |
|---|---|---|---|
| 选模板 → 开始 | 录制浮层 | — | 训练页计划段 |
| 点历史条目 | 训练详情浮层 | — | 训练页历史段 |
| 编辑模板 | 模板编辑浮层 | — | 训练页计划段 |
| 空白训练 | 录制浮层 | — | 训练页 |

### 4.3 从「周目标」出发

| 动作 | 目的地 | 带意图 | 返回落到 |
|---|---|---|---|
| 点某天 | 当天明细浮层 | — | 周目标页，且停在该周 |
| 「看这一周」 | 停留在周目标页 | 切周 | — |
| 「去训练」 | 训练标签 | `from: plan` | 周目标 |

### 4.4 从「教练」出发

| 动作 | 目的地 | 带意图 | 返回落到 |
|---|---|---|---|
| 「去记第一组」（无记录时） | 今日标签 | `from: coach` | 教练 |

### 4.5 从「我的」出发

| 动作 | 目的地 | 带意图 | 返回落到 |
|---|---|---|---|
| 导出/导入/备份 | 数据管理浮层 | — | 我的（设置段） |

## 5. 机制说明

### 5.1 三个模块各管一件事

| 模块 | 管什么 | 关键 API |
|---|---|---|
| `useNavigation` | 跨标签的**意图**与**来源** | `setIntent` / `takeIntent` / `originOf` |
| `useOverlay` | 浮层开关 | `openSession` / `startLive` / `openTemplateEditor` |
| `useBackLayer` | 返回优先级 | `requestBack` / `setBackFallback` |

### 5.2 返回优先级（唯一出口）

所有返回入口（安卓返回键、边缘滑动、浏览器后退）都走同一条链：

```
1. 有浮层打开？        → 关最上层浮层
2. 有 sheet/弹窗打开？ → 关它
3. 这个标签是跳来的？  → 回来源标签
4. 不是今日标签？      → 浏览器后退
5. 是今日标签          → 交给系统（安卓退出应用）
```

**不要在组件里直接监听返回键**，那会绕过这条链，出现"两个层同时关"或"关不掉"。

### 5.3 意图只生效一次

`takeIntent()` 取走即清空。目的地在 `onMounted` 调用一次，
不会因为组件重渲染而反复应用同一个意图（那会导致用户手动切段后又被弹回去）。

## 6. 新增页面/跳转时的检查清单

- [ ] 这是**平级标签**还是**深入一层**？
      深入 → 用 `useOverlay`，不要新增标签
- [ ] 跨标签跳转是否带了 `focus`？用户点这个按钮**期望看到什么**？
- [ ] 是否带了 `from`？用户在目的地按返回，应该回到哪？
- [ ] 按钮文案是否与实际落点一致？（"全部"必须落在列表，不是计划页）
- [ ] 浮层关闭后，底层标签的滚动位置和分段状态是否保留？
- [ ] 有没有绕过 `requestBack` 直接监听返回键？

## 7. 已知限制

| 限制 | 说明 | 影响 |
|---|---|---|
| 浮层状态不持久化 | 刷新页面会关闭所有浮层 | 可接受：浮层是临时视图 |
| 来源记录只保留最近一跳 | 连续跨标签 3 次，只记得最后一次 | 可接受：更长的链用户会用标签栏 |
| 无深链接 | 除标签外无法直接打开某场训练 | 暂不需要；未来做分享链接时再补 |
| `data` 写在 `Route` 里但不在标签栏 | 它由「我的」进入 | 视觉上属于浮层，实现上是标签 |

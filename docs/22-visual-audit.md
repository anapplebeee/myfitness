# 多视口视觉审计

日期：2026-10-25

## 0. 为什么会有这个脚本

真机验证（Xiaomi 15，369px 宽）通过后，用户反馈"细节问题还是有些多"。

真机只能看到**一台设备的一个宽度**，而布局缺陷往往只在特定宽度出现。
本轮实测就证明了这点：

> `flex` 布局的组行在 369px 正常，在 **360px 时勾选框直接压在"次数"输入框上**，完全无法点击。

360px 是 Galaxy S 系列、多数千元机的宽度——**比测试机更常见的尺寸，反而没测到**。

## 1. 用法

```bash
node scripts/visual-audit.mjs
```

输出：

- `shots/audit/<视口>-<页面>.png` —— 每个视口 × 每个页面的截图
- `shots/audit/issues.json` —— 完整问题列表

## 2. 视口

| 名称 | 尺寸 | 对应设备 |
|---|---|---|
| 360x800-se | 360×800 @3x | Galaxy S 系列、多数千元机 |
| 390x844-iphone | 390×844 @3x | iPhone 13/14/15 |
| 412x915-android | 412×915 @2.6x | Pixel 6/7、多数旗舰 |
| 430x932-promax | 430×932 @3x | iPhone Pro Max |

## 3. 检测项与判定

| 检测项 | 判定 | 说明 |
|---|---|---|
| 横向溢出 | **致命** | `documentElement.scrollWidth > innerWidth` |
| 元素越界 | **致命** | 元素左右超出视口，且不在横向滚动容器内 |
| 行内错位 | **致命** | 同一 flex 行内子项 top 差 > 12px（意外换行） |
| 文字被截断 | **致命** | `scrollWidth > clientWidth` 且无省略号 |
| 触控目标过小 | 观察 | < 44×44，白名单除外（分段控件、标签栏、芯片） |
| 字号过小 | 观察 | < 11px，标签栏除外 |

**为什么分成致命与观察**：10px 的列标签、40px 的图标按钮在各主流 App 里普遍存在，
逐个纠结收益很低。门禁应该拦"页面布局坏了"，而不是"设计偏好不同"。

## 5. 审计抓到的真实缺陷

| 缺陷 | 严重度 | 修法 |
|---|---|---|
| 360px 下勾选框与"次数"输入框重叠 | **P0，功能不可用** | 组行从 flex 改 CSS Grid，列宽分配制保证不重叠 |
| "跳过"竖排按钮掉行 | P1 | 改图标 + 固定 16px 列 |
| 小按钮触控区 36px | P1 | `::after` 外扩到 44px，视觉不变 |
| 输入数字偏左 | P2 | 居中 + tabular figures |

## 6. 审计**没有**抓到的问题

同一轮里，组件 `ReferenceError: Cannot access '_' before initialization`
（`SyncPanel` 的 setup 里提前调用了尚未声明的函数），导致整个同步面板渲染为空。

**视觉审计完全没发现它**——因为页面上没有布局异常，只是少了一块内容。
是 3 个同步 E2E 失败才暴露的。

结论：**视觉审计不能替代功能测试**。两者覆盖的是不同类别的问题：

| 工具 | 能发现 | 发现不了 |
|---|---|---|
| 视觉审计 | 布局崩坏、重叠、越界、触控过小 | 组件崩溃、逻辑错误、数据问题 |
| E2E | 功能不可用、流程断裂、持久化 | 只在特定宽度出现的布局问题 |
| 真机 | 触控手感、软键盘、手势冲突、GPU 渲染 | 不方便覆盖多尺寸 |

三者都需要，缺一不可。

## 7. 局限

- 用 Edge headless 渲染，与 WebView 的排版引擎同源（Chromium），但**不是同一版本**
- 不检测动画、过渡、滚动手感
- 不检测深色模式（当前产品只有浅色）
- 触控目标检测基于 `getBoundingClientRect`，`::after` 外扩需靠推断（已实现）
- **不能替代真机**：GPU 渲染差异、系统字体、软键盘行为都无法模拟

## 8. CI

`node scripts/visual-audit.mjs` 以退出码表示结果：致命问题 > 0 则失败。

```bash
npm run audit:visual
```

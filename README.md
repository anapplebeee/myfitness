# 铁馆 · 健身 AI 教练

一个不用装、不用登录的健身 App。训练计划、饮食配餐、每日打卡、动作库四块打通，模型与本地引擎双轨运行。

## 快速开始

直接双击 `index.html` 即可（纯静态、零依赖、无需构建、可离线）。

首次打开会先让你填身体数据，保存后到「计划」页生成计划：

- **让模型生成计划** —— 需要先在设置里填模型接口（见下）
- **用本地引擎生成** —— 不需要任何 Key，规则引擎当场算

生成完点「导入到日程」，之后在「今日」逐项勾选，或用一句话交给模型勾。

## 模型配置

设置 → 模型，填三样：

| 字段 | 示例 | 说明 |
|---|---|---|
| 接口地址 | `https://api.deepseek.com/v1` | 任何 OpenAI 兼容接口，通常以 `/v1` 结尾 |
| 模型名 | `deepseek-chat` | 通义 / 智谱 / Kimi / GPT 同理 |
| API Key | `sk-...` | 只存在本机 `localStorage`，不上传 |

填完点「测试连接」会真发一次最小请求验证。

**没填 Key 也能用**：热量与宏量营养素、训练分化、配餐、体重趋势全部由本地引擎计算；只有自由对话不可用。

## 三块能力

### 1. 模型当健身专家 + 营养师

- 「教练」页两个身份切换，各自独立的对话历史
- 每轮请求自动带上 `<data>` 数据块：身体数据、BMR/TDEE、目标摄入、今日日程、近 7 天完成率、体重趋势
- 「分析我的数据」：一次拉出训练/饮食层面的体检结论 + 两周内要改的 1–2 件事
- 计划生成走 `response_format: json_object`，返回结构化 JSON 后归一化入库，脏数据会被修正（组数越界、动作名对不上库、餐次热量缺失等）

### 2. 专业动作参考

44 个动作，每个都有：起始位置、分步动作要点、呼吸节奏、常见错误、教练提示、替代动作、组次与休息、离心-底部-向心节奏。

- 每张卡片带**肌群示意图**（前/后侧 SVG，主练深绿、协同浅绿）
- 计划里点动作名直接跳到该动作详情
- 详情页可「加入今天日程」

### 3. 打卡与模型交互日程

- 日程按天排布，勾选即完成；全部完成自动打卡
- 「一句话汇报」把自然语言映射到当天条目：*"深蹲和卧推练完了，晚餐没吃主食"* → 勾选/取消对应条目
  - 有 Key：模型解析，返回 `{completed, skipped, note, reply}`
  - 无 Key：本地分词 + 否定词识别（"没做"不会误判成完成）
- 连续打卡天数、近 7 天完成率、近 28 天热力图

## 算法口径

| 项目 | 口径 |
|---|---|
| BMR | Mifflin-St Jeor |
| TDEE | BMR × 活动系数（1.2 / 1.375 / 1.55 / 1.725） |
| 目标热量 | 减脂 −20%、重组 −5%、增肌 +12%，下限男 1500 / 女 1200 kcal |
| 蛋白质 | 减脂 2.0、重组 1.9、增肌 1.8 g/kg（BMI≥28 时按调整体重） |
| 脂肪 | 0.9 g/kg（下限 40 g），其余给碳水 |
| 配餐求解 | 蛋白源定量 → 脂肪源补差 → 蔬菜固定 150 g → 碳水按剩余热量补足；主食/蔬菜自带蛋白先扣除再迭代求解，直到总蛋白贴近目标 |
| 训练分化 | 2 天全身 / 3 天推拉腿 / 4 天上下肢 / 5–6 天推拉腿 |
| 动作筛选 | 复合动作优先，按器械条件与经验等级过滤（新手排除高阶动作） |
| 体重预警 | 周变化 > 体重 1% 时提示减重过快 |

## 数据与隐私

- **默认（本地模式）**：所有数据（体重、计划、日程、打卡、对话）只存在当前浏览器的 `localStorage`，换设备不会同步
- **可选（自托管模式）**：`node server.js` 后从 `http://<你的机器>:8787` 打开，前端自动识别同源 `/api`，数据落在 `data/state.json`（写入前自动留备份）
  - 该服务端目前是**原型**，端到端验证尚未完成，正式使用前请先跑一遍读写与备份回滚
- 模型 API Key 只在本机，直连你配置的接口，不经过任何中间服务
  - 注意：接入自托管模式后，Key 会随状态一起落到服务器文件（设计文档 §9.3 给出了把它移出 state 的方案）
- 设置页可导出/导入 JSON 备份，也可一键清空

## 边界

本应用输出的是通用运动营养学建议，不构成医疗建议。有伤病史、慢性病、孕产情况请先咨询医生。
